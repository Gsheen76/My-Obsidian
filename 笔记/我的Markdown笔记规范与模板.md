# 我的 Markdown 笔记规范与模板

## 1. 当前写作习惯

- 以中文为主，保留论文、模型、函数和工具的英文原名。
- 使用 Markdown 标题组织层级，论文和课程笔记常用编号，实验记录常用 `step`，项目档案常用功能模块分节。
- 经常使用 Obsidian callout 表达摘要、提示、结论和注意事项。
- 使用表格整理参数、指标、操作与结果；使用代码块保存命令、配置和最小复现示例。
- 研究类笔记重视方法、实验和结论，项目类笔记重视状态、架构和待办，速查类笔记重视可直接复制使用。
- 笔记之间通过 `[[双链]]` 连接，并在索引页按主题聚合。

## 2. 统一元数据

所有正式笔记推荐在文件开头使用 YAML frontmatter：

```yaml
---
title: 笔记标题
type: note # note / reference / experiment / paper / project / diary / index
tags:
  - 主题标签
summary: 一句话说明这篇笔记解决什么问题或记录什么内容。
status: active # 可选：active / archived / draft
source: 来源或项目位置 # 可选
updated: 2026-08-05
migrated: 2026-08-05 # 可选：结构迁移或批量整理日期
---
```

字段约定：

- `title`：与文件名基本一致，必要时使用更适合阅读的标题。
- `type`：帮助区分知识、论文、实验、项目、日记和索引。
- `tags`：使用稳定的主题词，优先使用已有标签，避免同义词重复。
- `summary`：只写一句话，回答“这篇笔记有什么用”。
- `status`、`source`、`updated`、`migrated`：按需要填写；`migrated` 用于区分结构整理日期和内容实际更新时间。

## 3. 通用正文骨架

```markdown
---
title: 笔记标题
type: note
tags:
  - 主题标签
summary: Summary。
updated: 2026-08-05
---

# 笔记标题

> [!summary] Summary
> 用一句话说明问题、方法或结论。

## 关键概念

- **概念 A**：定义、作用或与本笔记的关系。
- **概念 B**：定义、作用或使用条件。

## 正文

按主题拆分为二级标题；步骤、参数、公式、代码和结果放在对应小节中。

## 结论或当前状态

- 已确认的结论、可复用经验或当前完成度。

## 关联笔记

- [[相关笔记]]：说明关联原因。
- [[笔记/知识库/知识库索引]]：返回主题索引。

## 规划

- [ ] 待补充、待验证或下一步实验。

## 资料来源

- 原论文、官方文档、数据集或项目文件路径。
```

“正文”不是固定标题。已有笔记如果已经有清晰的章节结构，可以保留原来的章节名，只补充摘要、关键概念、关联笔记和收尾信息。

## 4. 按场景裁剪

### 论文阅读

推荐顺序：

1. Summary
2. 研究问题与背景
3. 关键概念
4. 方法
5. 实验与结果
6. 优点、局限与个人思考
7. 关联笔记
8. 资料来源

论文原文的章节编号可以保留；中文解释和原文标题并列时，优先保证术语可检索。

### 实验或课程任务

推荐顺序：

1. 目标与环境
2. 关键概念或理论依据
3. 操作步骤
4. 参数与代码
5. 结果与问题
6. 结论
7. 规划
8. 资料来源

`step1`、`step2` 可以继续使用，但应尽量改成能表达动作的标题，例如“配置投影参数”“重建并检查结果”。

### 项目档案

推荐顺序：

1. Summary
2. 项目定位与当前状态
3. 功能或模块
4. 架构与数据流
5. 运行、测试和发布
6. 已知问题与风险
7. 规划
8. 关联笔记
9. 资料来源

### 速查笔记

保留“概念 - 示例 - 注意事项”的短结构，不必强行加入完整的项目章节；至少提供 Summary 和关联笔记。

### 日记

保留按年份、月份和日期的时间线结构。日记只需要统一 frontmatter 和标签，不要求加入项目式的规划、资料来源等章节。

## 5. 标题、列表和代码约定

- 一级标题只保留一个，作为笔记标题；正文从二级标题开始。
- 二级标题表达主题，三级标题表达主题下的具体问题、步骤或案例。
- 同一层级的标题使用同一种语言和编号风格；论文原文编号可保留，不再额外套一层无意义编号。
- 一个列表项只表达一个事实或动作；较长说明拆成段落。
- 命令、路径、变量、函数和文件名使用反引号；多行代码标注语言。
- 公式使用 LaTeX，图片紧跟在解释它的段落或小节之后，并补充必要的图注。
- 结论优先写可验证的事实，猜测和待确认内容标记为“待验证”。

## 6. 双链与索引

- 关联笔记使用 `[[路径/笔记名]]`，必要时用 `|显示名称` 设置更短的显示文本。
- 新笔记至少连接一个上级主题或索引；跨主题笔记连接两个以上相关节点。
- 总入口是 [[笔记/知识库/知识库索引]]；索引负责发现笔记，笔记正文负责解释关系。
- 不为没有实际关系的笔记强行互链，避免形成噪声网络。

## 7. 迁移原则

- 先补充 frontmatter、摘要和标签，再整理章节，不直接重写已有正文。
- 研究记录、实验过程和日记保留原始时间线与上下文。
- 只有在标题层级明显混乱、重复或无法检索时才调整标题。
- “规划”和“资料来源”没有实际内容时可以省略，避免留下空壳章节。
- 每次整理后检查图片、代码块、公式和双链是否仍然可用。
