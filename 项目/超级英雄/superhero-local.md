# 超级英雄联盟本地单机改造项目

> 维护日期：2026-08-03
> 
> 项目类型：基于原版 APK 的离线、本地存档改造，不是重写游戏客户端。

## 1. 项目简介

本项目以根目录的 `original.apk` 为基础，保留原版 Android 客户端、Lua 界面、战斗表现、图片、音频和配置资源，只替换离线运行所需的少量 Lua 文件，并对原生 DEX 和 Android 清单做最小修改。

目标是让游戏在没有原服务器、没有支付 SDK、没有聊天服务的情况下仍能完成一条可持续游玩的本地流程：创建本地账号、创建角色、进入主界面、查看和管理资产、进行主线地图战斗、获得经验和奖励、保存进度并在重启后恢复。

原版的联网竞技、社交、公会、活动和支付入口不再访问真实服务器；这些功能按功能重要性分别使用本地规则、固定 NPC、模拟奖励或明确的本地模式数据承载。

## 3. 当前架构

### 3.1 请求路径

```text
原版 Lua UI
   -> shared/network.lua
   -> LOCAL_OFFLINE 分支
   -> shared/local_backend.lua
   -> shared/local_features.lua（通用功能路由）
   -> 应用私有目录 superhero_local_save.json
```

`network.lua` 在离线模式下不创建 HTTP 请求，而是直接调用本地后端，并继续使用原版的回调和 `util_json` 数据形状，因此大部分原版 UI 不需要重写。

### 3.2 本地存档

存档文件名为 `superhero_local_save.json`，写入 Android 应用私有可写目录。主要数据包括：

- 本地账号、角色、等级、经验、VIP 和资源栏。
- 英雄卡、装备、背包、仓库、阵容、装备槽和相关扩展字段。
- 主界面数据、主线世界地图、城市地图、建筑战斗进度和引导进度。
- 本地充值记录、首充状态、购买次数和本地功能状态。
- 商店、抽取、竞技、社交、任务奖励等模拟功能的计数和领取记录。

存档读取时会执行版本修复和字段补全；旧版本存档允许直接迁移，不要求用户先清除数据。关键进度使用单调合并，避免运行时空数据把已有角色、等级、阵容或引导回滚。

### 3.3 主线配置

源码目录中不直接保存 `shared/local_story_data.lua`。`tools/patch_apk.py` 会从原 APK 的以下配置生成压缩的本地 Lua 数据模块，并作为 `assets/lua/shared/local_story_data.lua` 写入新 APK：

- `map.config`
- `map_main_story.config`
- `map_title_detail.config`
- `map_fight.config`
- `role.config`

当前最新 APK 中生成的数据规模为：120 个主线城市、129 个地图、2885 个建筑、6159 个战斗条目、200 个等级经验配置。修改主线逻辑时应修改生成器或原配置来源，不要手工把生成文件塞回解密目录。

- 支付入口改成本地假充值，不调用支付宝、微信或其他支付 SDK；首充双倍、VIP 经验和购买记录写入存档。

### 资产和阵容基础（已接入）

- 资源栏、英雄卡、装备、背包和仓库的基础数据结构。
- 背包/仓库存取道具、卡牌、装备和法宝，数量和对象移动持久化。
- 阵容、装备槽、辅助位、命运位等基础阵型写回。
- 充值、资源和等级数据显示可从本地状态刷新。

### 通用离线功能层（已接入，仍需逐项深化）

`shared/local_features.lua` 已为大量原版路由提供统一的本地响应形状，当前覆盖：

- 商店和兑换的固定本地商品。
- 卡牌/装备抽取的本地生成和计数。
- 竞技场固定 NPC、排名和战斗奖励。
- 好友、队伍、公会的本地 NPC/公会数据。
- 日常、一次性奖励和领取去重。
- 英雄、装备等部分升级、进化、强化、锁定和解锁动作。
- 其他未专门实现的原版路由返回稳定的本地空数据或通用模拟数据，避免黑屏、卡死和无限加载。

这些响应的目标是保证 UI 可进入、可返回、可保存；它们不代表所有原版玩法已经完成等价实现。

## 7. 已知限制和风险

- 主线配置只有在重新运行 `patch_apk.py` 时才会重新生成；只修改 `decrypted-lua` 不会自动更新 APK 内的故事模块。
- 通用本地功能层目前优先保证入口和状态稳定，竞技、社交、公会、活动、复杂养成和多人玩法仍是模拟数据，不是完整的原服规则。
- 原版 UI 仍可能依赖某些深层配置或战斗资源；出现“进入后空白”时，应先检查对应路由的响应字段，而不是立即替换界面。
- 本地 APK 使用新签名。如果设备已安装原版同包名 APK，通常需要先卸载原版；卸载前确认原版数据不再需要。
- `superhero_local_save.json` 是用户进度。调试时不要随意删除；需要重置时应先备份并记录原因。
- 本地测试证书仅用于个人离线测试，不适合发布到应用商店。

- 自动遍历菜单和二级入口，收集未支持路由、Lua 异常、加载超时和缺失字段。

- 完成验收后输出最终 APK、SHA-256、存档位置和限制清单。

## 9. 日常维护流程

1. 先修改 `original-mod/decrypted-lua` 或 `original-mod/tools`，不要直接修改 APK。
2. 运行 Lua 语法检查和针对性 Python 回归测试。
3. 使用原始 APK 和当前 Lua 目录重新运行 `patch_apk.py`，确保故事模块同步生成。
4. 依次执行 `sign_v1.py`、`sign_v2.py` 和 `verify_apk.py`。
5. 如有 MuMu 条件，安装新包后执行入口遍历、实际操作、重启和存档恢复测试。
6. 保留旧 APK 和测试存档；在本文件更新日期、完成项、已知限制、产物路径和 SHA-256。

## 10. 维护原则

- 优先复用原版 UI、协议字段和配置，不为单个入口重复造一套界面。
- 所有会改变资产的动作必须是本地事务：校验资源、修改状态、保存、返回客户端缓存增量。
- 领取、扣除、战斗和充值都必须幂等，重复点击不能重复发奖或产生负数。
- 不恢复已经停服的真实联网请求，不接入第三方支付，不把本地存档上传到网络。
- 新增功能必须同步补充回归测试和本项目文档。
