# 2026-09-25 奖励回路果汁感

> [!summary] Summary
每日任务/签到闭环补反馈：领取时宠物说话+开心动画、七日里程碑台词、任务完成即时报信（每条一次）、零点晨间提醒。

## 改动

- **① 领取反应**：`DailyWindow._pet_react(text)`（say + happy 动画，全防炸）接入三个领取点——签到「签到成功，+N 宠物币！」、任务「任务奖励 +N 到账啦！」、全勤「全勤奖励 +N！每天都有你真好～」。
- **② 七日里程碑**：签到后 streak≥7 且 %7==0 追加「连续签到 N 天啦，你是最棒的！」。
- **③ 任务完成即时报信**：`PetWindow._notify_daily_ready` 挂 on_decay tick——扫当日任务块，新完成的（progress≥target 且未领）说一次「今天的『任务』完成啦，记得去领奖励～」；(日期, 任务键) 去重表防重播，跨日自动清；say 自带隐藏门（游戏/隐藏不扰）。
- **④ 零点晨间提醒**：`_midnight_rollover` 尾部 `interface_anchor_visible()` 时说「零点啦，新的一天！来签到吧～」。
- 配套：三个 claim 系 UI 方法补 `now` 透传（跨午夜测试口，与 core 同款三态）。

## 验证

- 测试 +3（报信恰好一次+已领不再报、领取反应含奖励数、七日里程碑台词含「连续签到 7 天」）；全量 **970 passed**。
- 真机冒烟：watchdog 对完成 quests[0]（陪它玩 1 次）只报一次；`_claim_daily_quest` 触发「任务奖励 +20 到账啦！」+[happy] 动画；当日已签时 `_do_check_in` 无反应（幂等路径不扰）。
- 重启 PID 27336。

## 设计取舍

- 报信放 on_decay 而非 record_action 内：core 保持纯逻辑，UI 噪声与状态机解耦；tick 级 dict 扫描成本可忽略。
- 不加音效：play_sound 有隐藏门且币声资产未定，say+动画已够反馈强度。

## 审查追记（同轮）

- 双轴 code-review 抓到一硬两软并全部修复：**硬伤=报信误挂 on_decay 睡眠分支**（醒着互动永不报信）→ 挪到 auto_sleep 之后醒睡统一扫；软伤=进程内去重集合重启/备份还原后重播 → `notified` 标记持久化进任务块（随日期重置自然清零）；异常静默 → 接 `quest_notify_error` 诊断埋点（修复过程中它当场抓到一次 AttributeError，日志体系首秀立功）。
- 修复中一次插入撞进既有 try 块打断语法——`git checkout` 回提交态重打，Bash 批量改代码后必须 ast.parse 先行再落盘。
- 全量 **970 passed**（两轮）。
