# 2026-09-29 高频路径全景基准

> [!summary] Summary
> 「继续优化」收口轮：全景基准显示各面板单开路径已到 Python 层地板（记录窗 1104ms 中 651ms 为原生 show），复用路径全部 50ms 级；多窗叠加的环境性开销（每日窗"重开 2297ms"实为与记录窗同屏的 DWM 开销）是测试误判源。

## 全景数据

| 路径 | 耗时 | 构成 |
|---|---|---|
| 记录窗首开 | 1104ms | 原生 show() 651ms + Python 构造/refresh ~65ms |
| 每日窗首开 | 575ms | 同为原生建窗为主 |
| 每日窗重开（单跑） | 48ms | 复用路径健康 |
| 商店复用开 | 48ms | 页缓存+imgcache 生效 |
| 每日窗"重开"（与记录窗同屏） | 2297ms | DWM/合成层多窗叠加开销（衰减型） |

## 结论

1. 单开路径已到 Python 层地板——剩余是 Qt 建窗原生一次性成本（850×960 QSS 大窗首帧渲染）。预建隐藏窗方案有 2026-09-24 的 DPI 钳制历史坑（125% 屏常驻停靠窗被 WM 钳缩），风险大于收益，不做。
2. 多窗叠加的慢是环境性（DWM），单路径复测确认后再定位——**性能测试必须隔离单路径**。

## 坑位沉淀

- 多窗叠加（尤其 850×960 大 QSS 窗同屏）的 DWM 开销会把单操作数字放大 10-40 倍——基准测试要关闭其他自建窗再跑。
- `show()` 的原生耗时（大 QSS 窗首帧）无 Python 侧解法——这类成本的正确位置是"复用窗口"（已全具备）。
