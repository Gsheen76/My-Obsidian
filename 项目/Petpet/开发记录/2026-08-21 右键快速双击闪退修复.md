# 右键快速双击闪退修复

关联：[[Petpet 总档案]]、[[菜单系统/宠物快捷菜单交互记录]]、[[开发记录/2026-08-21 宠物界面与动画一致性修复]]。

> [!bug] 用户复现
> 快捷菜单处于关闭状态时，在桌面小狗本体上快速双击鼠标右键，程序容易直接退出。

> [!success] 实施状态
> 方案 A 已在 `main` 完成并提交。新增测试经过 RED→GREEN；真实 Qt 子进程连续派发 100 轮右键按下、释放和系统菜单事件后正常退出。最终全量验证为 `621 passed in 76.15s`。

## 系统故障证据

Windows 应用日志在 2026-08-21 14:31:40 记录到实际崩溃：

- 应用：`D:\anaconda3\pythonw.exe`
- 故障模块：`Qt5Core_conda.dll 5.15.2.0`
- 异常代码：`0xc0000005`
- 故障进程：PID `32324`

这是 Qt 原生内存访问冲突，不是能够由普通 Python `try/except` 捕获的异常。

## 根因

1. 小狗右键同时经过 `PetWindow.mouseReleaseEvent()` 和 `PetWindow.contextMenuEvent()` 两个入口。
2. 已显示的 `BubbleMenu` 安装了应用级事件过滤器；菜单外鼠标按下会通过 `QTimer.singleShot(0, self._close)` 延迟关闭。
3. 快速第二次右键小狗时，旧菜单可能已经排队关闭，但小狗的释放和上下文菜单事件仍再次请求打开菜单。
4. 菜单使用 `Qt.WA_DeleteOnClose`。旧菜单关闭、Qt 对象删除和新请求交错时，可能访问已经失效的 Qt 对象并在 `Qt5Core` 内崩溃。
5. 原有 0.25 秒时间防抖只降低重复创建概率，没有消除已排队关闭与菜单复用之间的生命周期竞争。

## 采用方案 A

### 小狗本体右键不再被视为菜单外点击

`BubbleMenu.eventFilter()` 现在识别以下组合：

- `QEvent.MouseButtonPress`
- `Qt.RightButton`
- 事件接收者就是该菜单所属的 `pet`

满足时不安排 `_close()`，但返回 `False` 让右键继续交给小狗窗口处理。左键小狗、菜单外窗口点击、属性卡与菜单页面切换保持原行为。

### 复用仍可见的活动菜单

`PetWindow.open_bubble_menu()` 发现旧菜单仍可见且没有进入 `_closing` 时，不再关闭重建，而是：

1. `follow_pet()` 校正菜单位置；
2. `raise_()` 保持置顶；
3. `activateWindow()` 激活窗口；
4. 返回同一个菜单实例。

不可见、正在关闭或 Qt 包装对象已失效的菜单继续使用原有清理和创建路径。菜单预热、外观、按钮布局和页面切换未改变。
