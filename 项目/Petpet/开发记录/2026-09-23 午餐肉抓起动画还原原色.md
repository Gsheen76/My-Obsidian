# 2026-09-23 午餐肉抓起动画还原原色

> [!summary] Summary
> 「抓起效果很差、颜色有偏差」= 导入管线当年烘焙的四道校色叠加过冲（比 idle 偏亮偏灰白）。源图不在盘上，但四道全是逐像素线性运算——用 git 帧对验证模型后矩阵求逆，把 16 帧 drag 精确还原成源图原色（误差舍入级），导入工具默认校色一并退役。

## 背景

- 用户反馈：午餐肉**原皮**抓起（drag）动画效果很差、颜色有偏差，怀疑之前上过色，要求还原图片设置。
- 历史脉络（`git log -- drag/`）：04be5f7 首次导入 → a06fe02「匹配 idle 配色」→ 892fa44 换摇摆踢腿 16 帧（sat×1.189/bright×0.889）→ 96c84c1 修绿偏（green×0.96）→ b09b75f 调至低于 idle 鲜艳度（sat×1.153/bright×0.862）→ 379e315 再提亮一档。全部烘焙进 PNG。

## 取证

- **现状量化**（alpha≥32 像素均值）：drag sat .650 / val .807 / RGB(205.8,122.9,75.8) vs idle sat .644 / val .784 / RGB(199.8,118.6,74.4)——drag 整体偏亮偏灰白，三列对比图（idle|旧drag|恢复）经视觉模型目检确认「旧 drag 苍白、缺乏 idle 暖橙生气」。
- **源图搜寻**：repo/git/Downloads/Desktop/Pictures/Documents 全盘关键词+尺寸扫描，4×4 源图 0 命中（当年只提交了产物帧）。
- **关键转念**：ImageEnhance.Color（向亮度向量混灰）、Brightness（乘）、绿通道点乘——全是 RGB 上的**线性算子**，整链可合成一个 3×3 矩阵并求逆，无需源图。

## 验证（先证模型，再动手）

1. **模型精确性**：git 存有同一源图两套增益的产物（892fa44 帧 vs b09b75f 帧）。用合成矩阵从前者预测后者：误差均值 0.48/255、最大 3、**0 像素 >3**——线性建模精确成立。
2. **379e315 系数以数据为准**：对 b09b75f→379e315 帧差拟合通道比 = **1.0597**（三通道一致）；commit 消息写的「val gain 0.92」倒数是 1.087，与数据不符——**系数必须拟合，不能信消息**。
3. **双路交叉验证**：恢复后再从 892fa44 git 帧走另一条逆链（1.189/0.889）恢复，两路逐像素对比误差均值 1.82/255、最大 5——纯 8-bit 舍入，两路收敛到同一张源图。

## 改动

- `tools/restore_lunch_meat_drag_colors.py`（新增，入库）：四道链 sat1.153→val0.862→green0.96→×1.0597 合成求逆，16 帧原地恢复（git 即备份；幂等警告：二跑会过冲）。恢复后 sat 0.650→0.591、val 0.807→0.849。
- `tools/import_lunch_meat_grab.py`：**默认校色增益归 1.0**（恐龙 08-31、原皮 09-22 两次用户定稿均选原色）；校色改显式 `--sat/--val/--green` opt-in。
- 帧尺寸/manifest 不动（scale 0.95、fps 8 与颜色无关）。

## 坑位

- **烘焙校色可逆**：Color/Brightness/通道点乘皆线性，合成矩阵求逆即可从产物还原源色（±舍入），源图丢失不再是死局；动手前先用 git 里同源异增益的帧对验证模型。
- **commit 消息里的系数不可信**：379e315 说 0.92 实测 1.0597——增益类参数一律从帧差拟合。
