# 2026-09-28 闪退第六案延迟出表加固与按压延迟调优

> [!summary] Summary
> 用户报「游戏闪退/点击缩小太小/音效按键反馈有延迟」。minidump 取证把闪退定为无父窗保活家族第六案（qwindows→嵌套 notify×3→AV 读已释放对象），根因是 closeEvent 当场出表让最后引用在嵌套事件投递中同步析构——改为 2.5s 缓冲延迟出表；同轮完成按压幅度与全链路延迟调优。全量 1014 passed，真平台翻搅冒烟存活。

## 背景

纯缩放反馈统一轮（[[开发记录/2026-09-28 按键纯缩放反馈统一与四角锁定真根因]]）重启后，用户先后反馈三点：①游戏闪退；②点击缩小有点太小；③音效和按键反馈略有延迟，整体体验还要优化。

## 闪退取证（第六案）

- **时间线**：diag.log 最后事件 15:56:31 menu_close（无 unhandled_exception——原生崩溃绕过 excepthook）；WER 15:56:32 `pythonw.exe 42528` AV 0xc0000005，出错模块 `Qt5Core_conda.dll+0x1e3956`——与 9/13-9/25 家族五案**同模块同偏移**。
- **minidump**（pythonw.exe.42528.dmp，minidump 库解析）：主线程；调用链 = `qwindows.dll` 窗口过程 → `Qt5Widgets` 事件投递 → **Qt5Core notify 嵌套三层** → AV 读 `0xFFFFFFFFFFFFFFFF`（已释放对象的毒性内存）；Rdi 附近残留宽字符 `"HWND"`。小型 dump 未捕获堆，寄存器指向的堆对象不可读——具体窗口定不到，病理足以定案。
- **病理定案**：`KeepAliveTopLevelWindow.closeEvent` **当场 discard**——若那是最后一个 Python 引用，C++ 对象在**嵌套事件投递进行中**同步析构（dump 的 notify×3 正是这个场景），在途窗口事件随即打到已释放接收者。9/24 家族根治把析构从「GC 时机」挪到「close 时机」，但 close 时机同样有在途消息竞态。

## 修复

- **延迟出表**：`closeEvent` 改 `QTimer.singleShot(CLOSE_GRACE_MS=2500, drop)`，缓冲期内引用仍在注册表、在途消息排空后才允许析构。复用面板（宿主持引用）不受影响；无父 QDialog 全库审计无盲区（`PurchasePopup`/`MemoryProfileDialog` 唯一调用点均传父）。
- **守卫适配**：`test_parentless_window_guard` 基类测试改断言「close 后仍在表、缓冲期满才出表」；`test_menu_ui` 四个气泡保活断言加 `_drain_close_grace` 等待。
- **冒烟**：真平台 python 控制台进程（faulthandler 兜底）高频翻搅——菜单×15 连开关、say×12 换泡、五面板×4 开关循环、3.2s 缓冲排空——**存活退出 0**。

## 按压与延迟调优（用户②③）

- **按压加大**：FeedbackButton/`_TabButton`/`_ArtButton`/家园图片键/场景键内缩 3→5px；`_AvatarButton` 4→6px；装修分类签/放置收纳键 2→3px。
- **延迟收敛**：`RECOVER_MS` 与 `HomeSceneWindow.BUTTON_PRESS_FLASH_MS` 40→15ms（低于感知阈）；**点击音从回弹触发瞬间提前到 `mouseReleaseEvent` 松开瞬间**（家园/_ArtButton 本就即时）；BubbleMenu 悬浮缓动 0.25→0.4/帧（到位 ~160→~100ms）。
- 测试 pin 同步：场景键按压 -6→-10、头像 4→6。

## 验证

全量 **1014 passed**（exit 0）；冒烟存活；重启 PID 50728（15:56 崩溃进程的替代）。手感（按压幅度/跟手度/声音即时性）以用户实测为准。

## 评审二轮补丁

- `_drop` 加 `isVisible()` 守卫：复用窗口若在缓冲期内重新 show，到点不出表继续保活（防未来「仅靠本表保活+关后重开」的窗口失守）；C++ 已销毁的僵尸包装按 RuntimeError 捕获照常出表。评审确认 AGENTS「未同步」为误报（git-exclude 件不进 diff）；小键 5px 内缩实测无裁切（30×30 装修关闭键/分类签文字居中均安全）。

## 坑位沉淀

- closeEvent 里同步 discard 最后引用 = 嵌套投递期间的同步析构点——**出表类动作一律走定时器延迟**，别在事件处理路径上释放可能还挂着在途消息的对象。
- 小型 minidump（CrashDumps 默认档）只有栈没有堆：寄存器指向的对象读不了；取证到「家族签名+病理」即可动手，别恋战定位具体实例。
- `pip minidump` 本机 API 与记忆配方略有漂移（`f.reader`→`f.get_reader()`、`ExceptionList.thread_id`→`exception_records[0].ThreadId`、ThreadContext 要按文件偏移裸读）——配方思路不变，API 名现场探。
