# 隐藏问题清扫

> [!summary] Summary
> 全量 **787 passed** + 重启 PID 24664。排查面：runtime 依赖契约 / 死状态字段 / 假条件 / 重复逻辑 / 静默 except（18 处均为既定的资源回退策略，未动）/ TODO（零）。

## 1. runtime.txt 缺 Pillow + numpy（最严重）

`requirements/runtime.txt` 只有 PyQt5/requests，但 `petpet/home/window.py`、`ui/pet_profile.py`、`progression/ui.py` **运行时** import PIL 和 numpy——按 runtime.txt 装的新环境启动即 ImportError。CI 没抓到是因为 workflow 单独显式 `pip install Pillow numpy`。修复：runtime.txt 补两项；AGENTS「runtime 三件套」改**四件套**并注明"runtime.txt 必须与实际 import 一致"。**教训：CI 的依赖安装显式绕过了 requirements 文件，等于契约文件从未被验证——CI 应改为 `-r requirements/runtime.txt` + 测试专用件。**（记待办）

## 2. 平移移除后的死状态残留

全景轮删了 pan 链路，但 `viewport_x/viewport_pinned`（只在 toggle 写、无人读）与 `_manual_camera`（与 `is_decorating()` 完全同相的冗余标志）留了下来——两轮 code-review 都点过名。本轮清偿：撤全部写入与赋值，`_sync_scene` 条件简化为 `if not self.is_decorating()`；`home_scene_state` 的 normalize 键保留（旧存档 schema 兼容，读旧值无害）。测试撤两处 `_manual_camera` 断言。

## 3. pet.py 单实例竞态假条件

`return False if self._notify_existing() else False` 恒为 False 的假条件——但 `_notify_existing()` 的副作用（重试唤醒主实例）是真实意图。改为直白的三行（重试通知 + return False），行为零变化、语义可读。

## 4. memory.py 六处重复清洗推导

抽 `_clean_bucket(facts, bucket) -> list[str]`，merge（existing/incoming）/render/facts_differ/sanitize 全部换用；parse_profile_extraction 因输入形态不同保持原地（注释说明）。纯重构，25 条 chat/memory 测试全绿证等价。
