# 2026-09-20 闪退取证与说话气泡保活修复

> [!summary] Summary
> 用户上午 10:42 遇闪退（pythonw，PID 20876）。无 cdb 环境下用纯 Python 解析 WER minidump 完成法证：崩溃 = Qt5Core 访问违例**读 0xFFFFFFFFFFFFFFFF**（悬空指针），调用链 `QEventLoop → QGui 窗口系统事件派发 → qwindows.dll → Qt5Core 字符串扫描`——即「窗口销毁 vs 事件投递」竞态。排查自动睡醒（本会话复活的休眠代码）与多屏跨界均排除（存档 awake/energy 49.2；单屏 2560×1440，位置合法）。定位到 `SpeechBubble`——与 2026-09-14 已修复的 BonusBubble 同族的**无父顶层原生窗**，`PetWindow.say()` 的「close 旧泡→建新泡」使旧泡失去全部 Python 引用被 GC 连 C++ 窗口当场销毁。

## 法证过程（可复用的 AV 排查配方）

1. **入口三件**：`%LOCALAPPDATA%\Petpet\crash_dump.log`（faulthandler，Python 栈）→ Windows 事件日志 `Id=1000`（肇事模块 Qt5Core_conda.dll +0x1e3956）→ `%LOCALAPPDATA%\CrashDumps\pythonw.exe.<pid>.dmp`（WER 转储）。
2. **无调试器解 dump**：`pip install minidump`；异常流 `exception_records[0].ExceptionRecord`（注意属性嵌套与枚举包装）；x64 CONTEXT 直接从文件 Rva 裸读（偏移：Rsp=0x98、Rip=0xF8）；栈扫描=读线程栈内存逐 8 字节比对模块区间。RSP 相对帧链比全栈噪声少得多。
3. **关键证据**：AV 类型=读、目标地址 **-1**（垃圾指针）；Rdi 含 UTF-16 "HWND" 字样（窗口字符串迭代中）；帧链含 qwindows.dll+Qt5Gui 窗口事件派发；栈上无 Qt5Multimedia（音效排除）。
4. faulthandler 日志**跨次追加**：旧行号块（pet.py:2250）是历史崩溃，现行行号（2254=app.exec_）才是本次——按行号对齐当前代码分辨。

## 修复（照 BonusBubble 已验证方子）

- `petpet/ui/desktop.py SpeechBubble`：类级 `_keep_alive` 注册表（创建注册、closeEvent 离场）——对象保活到 Qt 自己完成关闭，杜绝「GC 先于事件」窗口。
- `closeEvent` 先 `stop()` `_hide_timer`：close 后对象释放，在途 timeout 事件不得再指向它（竞态最后一道闸）。
- 测试 `SpeechBubbleKeepAliveTests`（test_menu_ui.py，与 BonusBubble 保活测试同式）：无引用时 C++ 不被回收 + close 后离场。

## 坑位

- **同族无父顶层窗要一次清查**：BonusBubble 修了兄弟漏了 SpeechBubble——「无 parent + 频繁创建/销毁 + 原生半透明窗」三特征命中的组件都该走类级保活（当前桌面层仅剩 `_interactive_bubble` 由实例属性长持引用，安全）。
- **minidump 包 API 陷阱**：`exception.exception_records[0]` → `.ExceptionRecord`（ExceptionCode 是枚举对象需 `.value`）；`ThreadContext` 是 Rva 定位符不是已解析寄存器，直接按文件偏移裸读最稳。
- WER 转储目录（`%LOCALAPPDATA%\CrashDumps`）在本机长期累积 pythonw.dmp——历史六枚对应 09-11~15 的 BonusBubble 风暴，本次为新品种。
