# 2026-09-14 状态卡v2修订与闪退根因修复等八轮

> [!summary] Summary
> 状态卡线的 v2 修订与文字显示四连修：用户交自行去背景底板并定三项修订（去百分比数值、去挂板名字、状态名加大加清晰）→ 整卡预渲染缩放致文字糊化，拆 `render_status_card_art`（底板）+ `draw_status_card_overlay`（场景画笔实时叠画）治本 → 中心锚定坐标系错位补 translate → 去粗体+21px+像素网格对齐二修 → 字号矩形偏移速修。另有闪退线：Windows 事件日志实锤三天三次同点位原生崩溃，PE 导出表反查确诊 BonusBubble 无父创建且不留引用、被 GC 连 C++ 回收后动画定时器信号投递崩溃，类级注册表 `_keep_alive` 保活修复；`pet.py` 入口装 faulthandler 留双保险。全量 854 passed；第八轮遮挡闪烁滞回带以 ±6px 消家具底线临界翻转（854→856，随 v1.7.3 发布收口）。

## 轮次记录

**状态卡 v2 修订（2026-09-14）**：用户交自行去背景版（真透明 1605×980）替换底板；三项修订——**去掉百分比数值、去掉挂板名字、三条状态名加大加清晰**（19px 加粗 #5a3d28，条延长至 216px 宽无右端数值区）。凹槽带复核 (95,135)/(146,186)/(198,238) 与常量 ±1px 无需调。已死的 value_rects 函数与挂板常量删除、测试同步。坑：重写时把 `font = painter.font()` 连名字块一起删了（NameError）——删块时检查块内初始化是否被下游依赖。全量 852，重启 PID 见 restart_pet23 动态输出。

**状态卡文字模糊根治（2026-09-14 第二轮）**：用户实机截图确认标签文字非常模糊。根因：**整卡（底图+文字）预渲染进 840×556 位图再缩放绘制**，文字随位图重采样糊化（之前 offscreen 无字体，我的自检渲染里文字是空白，没抓到）。治本拆分：`render_status_card_art`（公开，只出底板图）+ `draw_status_card_overlay`（公开，场景画笔实时画圆点/标签/进度条，TextAntialiasing）——家园 `_draw_furniture` 状态卡分支画底图后**以场景画笔按最终分辨率叠画内容**，furniture 字典两处改存底板；`render_home_status_card`（底图+overlay 预渲染）仅剩商店/预览用途。验证：1x 与 0.5x 两种显示尺度文字均清晰；全量 **852**；动态重启。坑位回顾：删名字块时连带删了 `font = painter.font()` 初始化（NameError）——**删代码块要检查块内初始化的下游依赖**。

**状态卡字错位修复（2026-09-14 第三轮）**：用户报家园状态卡文字错位。根因：`_draw_furniture` 坐标系**中心锚定**（底图画在 (-w/2,-h/2) 起），而 overlay 按 (0,0) 起点画——全部内容偏移 (+w/2,+h/2)；商店预览没错位是因为那边底图本就画在 (0,0)（两处坐标系不一致是隐患）。修复：overlay 调用前 `painter.translate(-w/2, -h/2)`。测试：像素证据契约（饱腹彩点必须落在 卡左上+(71,115) 且为橙色，不依赖字体）——注意断言坐标要加 `_scene_content_offset()`。全量 **853**。

**文字模糊二修（2026-09-14 第四轮）**：用户复检仍糊成一团，建议方向=高分辨率字/去加粗。落地三招：**去粗体**（小字号粗体中文笔画粘连是糊感主因）+ **19→21px** + **像素网格对齐**（文字矩形 y 取整，半像素偏移会让小字发虚）。真实平台锐度实测：字形边缘平均梯度 101/255、强边缘 331 处（放大图笔画干净）。全量 853，动态重启。

**文字垂直错位速修（2026-09-14 第五轮）**：二修改字号时矩形偏移算错（22px 高用 -21 而非 -11，文字上移 ~10px）。修正后像素级验证：三条槽文字中心偏差 ≤0.5px。全量 853。

**闪退排查（2026-09-14 第六轮）**：用户报闪退。Windows 事件日志实锤：**Qt5Core_conda.dll 访问违例（0xc0000005，偏移 0x1e3956），三天三次同点位**（09-13 15:42 / 09-14 10:18 / 09-14 16:56）——同一 bug 复发，非单实例假象（进程全灭）。原生崩溃 Python 层无栈——**pet.py 入口装 faulthandler**（崩时自动落全线程 Python 栈到 `%LOCALAPPDATA%\Petpet\crash_dump.log`，启用失败不影响启动）。压力复现：家园开/关/装修/滚动/选中/状态卡变换 30 轮 windows 原生平台无崩溃——触发在更隐蔽路径（疑线程/定时器时序），等下一次崩溃的栈即确诊。PID 30032。

**闪退根因修复（2026-09-14 第七轮·确诊）**：不等转储，用 PE 导出表把崩溃偏移 0x1e3956 反查到 **QObject::qt_static_metacall**（+0xec6）= 信号投递给已销毁接收者。全仓排查短命对象连接后定位：**BonusBubble 无父创建、升级/好感升级两处裸调用不留引用**（pet_window.py:792/796）→ Python GC 连 C++ 回收 → 33ms 动画定时器事件投递到已释放接收者 → AV。频率（每日一两次升级时刻）与三天三次的分布吻合。修复：`BonusBubble._keep_alive` 类级注册表自持保活，`closeEvent` 移除（含 `_last_bonus` 覆盖竞态一并消除——覆盖后旧气泡失去最后引用的场景同样被注册表兜住）。TDD 契约：无引用+gc.collect 后 weakref 存活且 C++ 未删；close 后移出注册表。faulthandler 继续留任（若复发即有双保险栈）。全量 **854**。

**遮挡闪烁滞回带（2026-09-14 第八轮）**：日志判读（1542 次翻转）——翻转时键差中位 1.1px、p90 4.4px，坐实临界抖动（宠物在家具底线 ±几像素晃动逐帧换层）；有 3 秒 4 连翻爆发样本。修复：`OCCLUSION_HYSTERESIS_PX=6.0` 滞回带——相对层确立后须越出 ±6px 才翻转，带内保持上一帧层级（家具深度键挪到宠物同侧 1px 实现）；翻转埋点继续留任，日志改为只记真实越带翻转。TDD 4 例（带内保持/越带翻转/带内回晃不回跳/对照组正常）。旧日志清空换新基线。全量 **856**。
