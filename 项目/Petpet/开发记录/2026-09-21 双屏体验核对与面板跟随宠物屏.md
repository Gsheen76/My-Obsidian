# 2026-09-21 双屏体验核对与面板跟随宠物屏

> [!summary] Summary
> 用户换回双屏（虚拟桌面 5120×1446，宠物常驻右屏 x=3778）要求「看看效果如何，不对的修掉」。逐条核对多屏相关代码路径后修一处家族性 bug：面板打开位置永远主屏居中，与 `show_near_pet` 的名字和聊天/设置页的既有正确范式矛盾。

## 核对清单（实际布局：左主 2560×1440 + 右 2560×1440，等 DPR）

| 路径 | 结论 |
|---|---|
| 聊天窗 `show_near_pet` | ✓ 已用 `pet.interface_screen_rect()`（正确范式） |
| 设置页 `show_near_pet` | ✓ 同上（有测试钉住 1920×1080 宠物屏居中） |
| 家园窗口锚点 `_screen_rect` | ✓ 已用 `pet.current_screen_rect()` |
| 说话气泡 `_available_screen_rect` | ✓ `screenAt(宠物中心)` |

| **商店/成就/记录/小游戏中枢+两游戏（CozyProgressWindow）** | ✗ 永远主屏居中 → **本修** |

## 修复

- `petpet/ui/common.py` 新增 `pet_screen_rect(pet)`：优先 `interface_screen_rect`（生产 PetWindow 的锚点逻辑）→ `current_screen_rect`（测试夹具）→ 主屏可用区；QRect 类型校验 + RuntimeError 兜底。
- `CozyProgressWindow.show_near_pet` 与 `PetProfileWindow.show_near_pet` 改用该帮助函数——面板在**宠物所在屏**居中，跨屏逗狗时商店不再弹到另一块屏。
- 测试：`DualScreenPanelPlacementTests`（右屏宠物 → 记录/商店落位 x∈[2560,5120)，RED 先行）；旧测试 `test_progression_window_opens_centred_on_the_screen` 期望从主屏改为夹具宠物屏。

## 追加：任意屏幕自适应（同日第二轮，用户指令「别的尺寸也要生效」）

初版只换了落位屏，面板尺寸仍在**构造时按主屏**收缩一次——宠物屏更小（如 1366×768 副屏）时 850×960 面板溢出居中出界（y 可为负）。通用化：

- `common.center_window_on_screen(window, screen, ...)`：**show 期**按目标屏收缩（保 520×560 最小可用 + 30/35 边距）→ 几何居中 → 整体钳进屏内；大屏零改动。接进 CozyProgress / PetProfile / Settings 三处 `show_near_pet`（聊天窗本就 show 期自适应）。
- 测试 `AdaptivePanelPlacementTests` 三例：小屏收缩入界（**需显式预置 850×960 构造尺寸**——offscreen 主屏 800×600 会把构造尺寸先缩掉造成空转绿）、负原点左屏落位、大屏不误缩。
- 几何居中公式 `(screen.width()-w)//2` 与 `QRect.center()` 的「宽-1」约定差 1px——以几何为准，旧期望同步。

**坑位**：①夹具假窗口常只有 `size()` 没有 `width()/height()`——帮助函数全程用 size 计算值，勿混用两套取值；②offscreen 主屏只有 800×600，凡测「大屏构造」尺寸必须显式 setFixedSize 预置。
