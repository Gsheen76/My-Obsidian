# 更新确认后误取消下载修复

> [!warning] 工作区边界
> 本修复当前位于 `D:\Agent_project\Petpet` 根工作区（版本 `v1.3.2` 的维护副本），尚未移植到 `home-scene-system` 的 `v1.5.2` 开发工作树，也未发布。

## 问题与根因

玩家在“发现新版本”对话框中点击确认后，旧实现会在确认按钮处理期间立即创建下载进度框。Qt 随后分发的鼠标释放事件可能落到新窗口的“取消”按钮上，导致下载尚未开始就设置取消事件。

## 修复

- `TrayApp._on_update_result()` 不再直接调用 `_start_update_download()`。
- 改用 `QTimer.singleShot(0, ...)` 将下载窗口创建延后到当前确认事件处理完成后的下一轮事件循环。
- 继续捕获确认时的 `update_info`，因此延后执行不会读取被后续 UI 操作修改的状态。

这个调整只改变窗口创建时机，不改变更新检查、下载、校验、替换或重启流程。

## 回归验证

- 新增菜单 UI 回归测试：确认 `_start_update_download()` 不在确认回调中同步执行；执行延后回调后，原更新信息会被准确传入。
- `python -m pytest -q tests/test_menu_ui.py -k update_download_starts_after_confirmation_event_finishes`：`1 passed, 26 deselected`。
- `git diff --check`：通过；仅有 Git 的 LF/CRLF 工作副本提示。
