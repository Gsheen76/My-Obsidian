# 2026-09-08 商店滚动条常驻统一内容宽

> [!summary] Summary
> 用户反馈：滚动条出现时挤在内容区里，有滚动条/没滚动条的页内容宽窄、比例不一。定稿方案：`CozyProgressWindow` 滚动条常驻（槽体 QSS 透明，无溢出时手柄零宽＝隐形空带）+ 内容布局右边距常设 15px。744 passed + 真机两页等宽实测（773 ≈ 2×381+12）+ 双页截图验收 + PassThru 重启（PID 23356）。

## 改动

| 项 | 内容 |
|---|---|
| `petpet/progression/ui.py`（CozyProgressWindow） | `setVerticalScrollBarPolicy(Qt.ScrollBarAlwaysOn)`；`content_layout.setContentsMargins(1, 5, 15, 5)`（右边距 10→15 常设）。视口宽度恒定＝滚动条 11px 永远计入，所有页（商店/成就/记录，凡 CozyProgressWindow 派生）卡片等宽；内容与滚动条带保持 ~4px 间隙 |
| `tests/test_progression_ui_boundary.py` | 回归测试：策略 AlwaysOn + 右边距 15 + 内容宽==视口宽 |

## 排坑记录（重要坑位）

- **首选方案 `setViewportMargins(0,0,15,0)` 被 QSS 样式化的 QScrollArea 压坏**：隔离裸 QScrollArea 实验完全正常（内容宽 -15、滚动不变），但接进 CozyProgressWindow（带 PANEL_STYLE QSS）后真机礼物卡被压成 118px 高、scrollMax=0（视觉确认压扁）。A/B（去 gutter 恢复正常 295px/885）实锤冲突。教训：**样式化滚动区勿用 setViewportMargins 预留带，用"滚动条常驻 + 布局边距"实现等宽**。
- **诊断脚本时序噪声**：`show → grab → refresh/_set_page → grab → 测量` 会拿到布局未收口的中间值（同一窗口两次测量 784/640 宽），一度误导方向；干净时序（构造 → 定页 → show → grab → 一次测量）+ 每方案独立进程 + 2×2 矩阵二分才定位。**测量布局一律用干净时序**。
- **offscreen 字体缺失会让卡高塌陷**（布局最小高度变小）→ 溢出/滚动断言在 offscreen 不可靠，这类断言只上 Windows 平台脚本。

## 同日追加：礼物页分栏模仿套装页（chipBar/chipTab）

用户指示礼物页分栏模仿套装页宠物选择器，随后追加定稿：**两处分栏都要等分铺满整行（有几个分几等分）**。把原 `outfitPetSelector/outfitPetTab` QSS 抽成**通用 `chipBar/chipTab` 属性**（规则不变：#f4e2d2 托盘 + #e9c9b1 边框 radius 18、透明底棕字圆角钮、hover #ffece1、checked 珊瑚 #f28f76 白字），套装页与礼物页共用；两处分栏最终形态：**chipBar 托盘样式 + 按钮全部 Expanding 等分铺满（去尾部 stretch）+ QButtonGroup 互斥**。真机实测礼物四键精确等宽 185px、套装两键 311/310（1px 取整差）。验证：全量 744 passed + 双页截图验收（等分铺满/选中态正确）+ PassThru 重启。坑位：离屏字体缺失使按钮最小宽不齐，**像素等宽断言在 offscreen 不可靠**——测试断言布局不变量（无 stretch 项 + Expanding 策略），像素等宽走 Windows 实测。
