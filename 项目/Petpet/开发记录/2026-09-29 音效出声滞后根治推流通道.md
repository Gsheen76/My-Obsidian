# 2026-09-29 音效出声滞后根治推流通道

> [!summary] Summary
> 用户「要点下去瞬间出声」。根因定案：QSoundEffect 的 WASAPI 输出缓冲 ~500ms（API 返回 0.002ms 但出声慢半秒——此前所有优化都在测错的指标）。换 QAudioOutput 常开推流，出声 ~10ms。全量 1018 passed。

## 根因与通道谱系

| 通道 | 出声延迟 | 依据 |
|---|---|---|
| QSoundEffect（Qt5 Windows/WASAPI） | **~500ms** | 用户体感「明显慢半秒」+ Qt5 已知输出缓冲问题 |
| winsound（waveOut） | ~150ms | 用户在 winsound 轮的体感「慢一点」 |
| **QAudioOutput 常开推流** | **~10ms** | 欠载态 write 直进播放头，延迟≈一个 WASAPI 周期 |

**关键失误复盘**：此前四轮音效优化全部以「API 返回时间」为指标（0.002-9ms 即判快）——**API 快≠出声快**。用户三次反馈延迟（winsound 轮「慢一点」、单实例轮「还是慢」、本轮「明显半秒」）全被 API 数据掩盖。

## 终版实现（petpet/app/sounds.py）

- `prewarm()`（pet.py main 调用）：`QAudioOutput.start()` 开常开推流通道（零出声）。
- `play_click()`：`io.write(pcm)`——欠载态（缓冲空）写入即播；音量预乘进样本（推流无设备旋钮，`VOLUME` 改动需重载 PCM）。
- 原型实测：15×write ≤1.4ms、状态机 Active→Idle 自动往返（欠载恢复语义成立）。
- 兜底链：推流失败→winsound→非 Windows 用 QSoundEffect 单实例。
- 测试：throttle mock 改 `io.write` 计数。

## 验证

20 连点 API 最坏 57ms；全量 **1018 passed**；重启 PID 28208。出声延迟的最终验收以用户耳朵为准（~10ms 低于感知阈）。

## 坑位沉淀

- **音频延迟必须测出声时刻**（环回录音/示波），API 返回时间是被缓冲掩盖的假指标——本日四轮返工的教训。
- QSoundEffect 的缓冲大小在 Qt5 不可配置，Windows 后端就是半秒级——低延迟场景弃用。
- QAudioOutput 推流的欠载态是特性：平时缓冲空，write 即播——不需要持续供静音。
