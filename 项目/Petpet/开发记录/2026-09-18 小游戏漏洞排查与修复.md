# 2026-09-18 小游戏漏洞排查与修复

> [!summary] Summary
> 用户指令「自建游戏还有什么漏洞，自主计划并修复，查漏补缺」。通读 `petpet/minigames/ui.py`（927 行）+ 结算核心 `award_minigame_coins` + 既有测试，逐项取证后确认两个真漏洞并 TDD 修复；其余五类疑点取证后排除（含结算一致性、初始化时序、token 取消链、公平性、关闭竞态）。

## 侦查范围

- 金币雨 `CoinCatchCanvas/CoinCatchGameWindow`、幸运爪爪 `ShellShuffleCanvas/LuckyPawsGameWindow`、枢纽 `MiniGameHubWindow` 全量通读。
- 经济面：`award_minigame_coins` 无上限发放（`reward=requested`），UI 文案「获得 {requested} Pet币」与实发恒一致——**排除**结算不一致疑点。
- 时序面：`CozyProgressWindow.__init__` 不调 `refresh()`，`show_near_pet()` 才调——hub/game 窗口初始化顺序无陷阱（**排除**）。
- 取消链：幸运爪爪跨轮 `QTimer.singleShot` 全走 token 守卫（canvas `_token` + 窗口 `_game_token` 双层），关窗后回调不触 Qt 调用——**排除**销毁后崩溃风险。
- 公平性：杯子只做相邻交换且禁止立即重复，全部排列可达、答案跟动画身份走（既有测试钉住）；`rng` 可注入——**排除**作弊面。
- 设计面：幸运爪爪中途关窗丢弃已猜对轮次的奖励——「每局按成绩结算」既有设计（测试钉住完成才结算），**不改**。

## 漏洞一：按键规范违规（三处裸 QPushButton）

- 现象：`minigames/ui.py` 的枢纽卡「开始」×2（`_game_card`）与两游戏窗「开始游戏」×2（实为 283/704/893 三处创建点）用的是裸 `QPushButton`，无悬浮放大高亮/按住内缩压暗/回弹 40ms 后触发。
- 根因：2026-09-11 按键反馈全应用清偿轮覆盖了 chat/settings/tutorial/controls，**漏掉了 minigames 模块**（它从不 import FeedbackButton）。
- 修复：三处换 `FeedbackButton`（与 `CozyProgressWindow` 同源 import）。测试：`MiniGameFeedbackComplianceTests`——三窗 `findChildren(QPushButton)` 非 FeedbackButton 残留为零（照 09-11 清偿轮的验证式）。

## 漏洞二：金币雨过期点击窗口

- 现象：回合截止时刻已到、但 33ms 周期的结算 tick 尚未跑到的间隙里，点中金币仍计 `hits`、加 `earned_coins`（且此时 `coin_value_for_remaining(0)`=2）。
- 根因：`mousePressEvent` 的门是 `self.running` 标志（由 tick 翻转），不是时间本身；点击路径算了 `remaining` 却不检查。
- 修复：`remaining <= 0.0` 提前返回（不计分、不奖币、不重置连击）。测试：`CoinCatchExpiredClickTests`——过期点击零计分 + 存活点击仍计分（护栏）两例。

## 坑位

- **给 QWidget.mousePressEvent 喂 Mock 事件会在 super() 分支炸**：PyQt5 对 C++ 槽参数做类型检查，`super().mousePressEvent(Mock)` 抛 `TypeError`——测鼠标路径直接构造真 `QMouseEvent`（`QEvent.MouseButtonPress + QPointF + 按钮×2 + 修饰键` 五参重载）。
- **改导入行先 grep 块内引用**：本轮把 `QPoint` 换 `QPointF` 时漏看测试体还在用 `QRectF`，连续两次 NameError 才补齐——HANDOFF 已有同类坑（删块检查块内初始化），此为导入版变体。
