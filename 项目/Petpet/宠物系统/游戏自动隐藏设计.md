# 游戏自动隐藏设计

> [!summary] Summary
> 用户需求（2026-09-08）："检测到有其他游戏启动时自动隐藏，在设置里增加开关"。实现为 `petpet/app/game_guard.py`（win32 前台采集 + 纯函数判定）+ PetWindow 2 秒轮询隐藏/恢复 + 设置页开关 `hide_in_game`（默认开）。当天即被用户真实游戏会话（英雄联盟全屏）验证生效。

## 1. 判定：双信号（满足其一即"游戏中"）

| 信号 | 覆盖场景 | 误报控制 |
|---|---|---|
| 前台窗口与所在显示器交集面积 ≥98% | 全屏/无边框窗口化游戏（绝大多数） | 最大化普通窗口只占工作区（不含任务栏 ~48px），覆盖不足不触发；全屏视频播放器会触发（视为合理行为） |
| 前台进程路径命中平台关键词（steamapps/Epic Games/WeGame/riot games/battle.net 等） | 小窗口化游戏补漏 | 仅命中游戏平台安装目录口径 |

排除项：自身窗口（winId）、自身进程（sys.executable + 源码目录）、桌面壁纸层（Progman/WorkerW 类）、explorer.exe。

采集与判定分离：`collect_foreground_info()`（win32 ctypes：GetForegroundWindow/GetWindowRect/MonitorFromWindow/GetClassNameW/OpenProcess+QueryFullProcessImageNameW）返回普通 dict，`is_game_present(info, ...)` 纯函数可离线测试；非 Windows 平台采集恒 None → 功能空转（macOS 暂不实现）。

## 2. PetWindow 状态机

- 2 秒 QTimer（`_game_guard_timer`）→ `_on_game_guard_tick`：游戏中且可见 → `hide_overlays()+hide()` 并置 `_game_auto_hidden=True`；游戏结束且 `_game_auto_hidden` → `show()+raise_()` 清标记。
- **只恢复自己藏的**：手动隐藏走 `set_user_visible(False)`（`_user_hidden` 标记），游戏结束不会把手动藏的小狗拉出来；反之自动隐藏期间用户手动显示/隐藏也不被覆盖。
- `_maintain_desktop_presence`（5 秒存在守卫）新增放行：`_game_auto_hidden` 时不把自动隐藏拉回来。
- 设置 `hide_in_game` 关闭时：停表 + 若正处自动隐藏则立即恢复。

## 3. 设置

`DEFAULT_SETTINGS["hide_in_game"] = True`（旧存档无键默认开）；设置页 `SWITCHES` 一行「游戏中自动隐藏 · 检测到其他游戏运行时藏起小狗，游戏退出后自动回来」，保存即 `apply_runtime_settings → _sync_game_guard_timer` 启停。

## 4. 验证

- offscreen 全量 **756 passed**（新 `tests/test_game_guard.py` 12 条：判定纯函数 6 + 设置默认/往返 + 窗口隐藏/恢复/手动互不打扰/启停）
- Windows 跨进程端到端：独立 pythonw 全屏辅助窗（避开自身进程排除）→ 宠物真隐藏 → 辅助窗退出 → 真恢复，PASS
- **真实会话验证**：重启后用户正在运行英雄联盟（RiotWindowClass 全屏 + WeGame 路径双命中），宠物窗口即全部自动隐藏——功能上线即实战生效
- 设置页截图验收：新开关行与说明文字正常

## 5. 已知边界

- 小窗口且非平台目录的游戏检不到（无通用"游戏"判定标准）；全屏视频/演示也会触发隐藏（与游戏同处理）
- 检测有 ≤2 秒轮询延迟（游戏启动到隐藏最多 2 秒）
- Windows 专用；macOS 端开关可见但空转
