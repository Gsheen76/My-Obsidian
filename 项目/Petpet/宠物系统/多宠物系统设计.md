# 多宠物系统设计

> [!info] 当前状态
> 设计已确认，尚未开始源码实现。当前首期目标是把桌面和家园统一显示为“午餐肉”，并建立可扩展的宠物注册、购买和切换基础；“冰淇淋”作为现有家园小狗的第二只宠物显示在商店中，正式动画资源后续补齐。

## 1. 目标

当前桌面宠物和家园宠物的形象差异过大。后续不再把它们视为同一只小狗在不同场景中的两套模型，而是明确设计为多只独立宠物：

- 桌面端默认宠物：午餐肉。
- 家园端原有小狗：冰淇淋。
- 首期启动后，桌面和家园都统一显示午餐肉。
- 商店新增“宠物”栏目，显示可购买和切换的宠物。
- 玩家可以修改每只宠物的昵称；“午餐肉”和“冰淇淋”只是初始默认名字。
- 后续上传新宠物动画时，直接补充对应资源，不重新设计存档和切换逻辑。

## 2. 已确认的数据边界

存档采用“玩家共享数据 + 每只宠物独立数据”的结构。首期仍可保留在一个 `pet_state.json` 中，避免升级时增加多文件迁移风险。

### 玩家共享

- 当前宠物 `active_pet_id`。
- 已拥有宠物 `owned_pet_ids`。
- 等级和经验。
- Pet币余额、收入和消费记录。
- 家具库存、家具位置、收纳状态和变换数据。
- 成就、强化、小游戏成绩和其他玩家账户进度。

### 每只宠物独立

- 宠物稳定 ID、默认名字和玩家昵称。
- 饱腹、心情、精力和睡眠状态。
- 好感点、好感等级及其增长缓冲。
- 互动统计中属于宠物本身的部分。
- 桌面位置、家园位置和各场景临时状态。
- AI 聊天记忆、用户画像和聊天历史。

切换宠物只改变 `active_pet_id`，不重置或复制任何宠物数据。桌面窗口和家园窗口始终读取同一个当前宠物，因此不会出现桌面显示午餐肉、家园显示冰淇淋的不同步状态。

## 3. 旧存档迁移

- 新用户默认创建并拥有 `lunch_meat`，默认激活它，默认昵称为“午餐肉”。
- 旧存档当前已有的名字、属性、好感、睡眠状态和位置迁移到午餐肉，保留玩家已经进行的养成进度。
- 旧的 `memory.json` 与 `memory-home.json` 作为历史兼容来源，合并到午餐肉的聊天记忆；后续每只宠物使用独立记忆 profile。
- 等级、经验、Pet币、家具、成就、强化和购买记录继续保留在玩家共享区。
- `ice_cream` 作为第二只宠物加入注册表，但首期不自动拥有，使用独立默认属性和空白聊天记忆。
- 迁移必须幂等：重复启动不能重复合并聊天记录、重复发放货币或覆盖玩家已经修改的昵称。

## 4. 宠物注册表与资源

新增运行资源注册表：

```text
assets/runtime/pets/manifest.json
```

每只宠物由稳定 ID 标识，并声明默认名、商店价格、预览图、桌面资源、家园资源和已有动作。示意：

```json
{
  "id": "lunch_meat",
  "default_name": "午餐肉",
  "original_price": 0,
  "discount": 1.0,
  "price": 0,
  "preview": "pets/desktop/poses/idle.png",
  "desktop": {
    "animations_manifest": "pets/desktop/animations/manifest.json"
  },
  "home": {
    "idle": "pets/desktop/poses/idle.png"
  }
}
```

冰淇淋首期为可购买宠物：原价 `1000 Pet币`，按 `76 折`销售，实际支付 `760 Pet币`。购买规则由注册表提供，扣除玩家共享的 Pet币；购买成功后自动切换到冰淇淋，重复购买不会再次扣款。

首期资源规则：

- `lunch_meat` 直接复用当前已经验证的桌面静态姿势和连续帧动画。
- 家园首期也使用午餐肉资源，不再显示当前旧家园小狗资源。
- `ice_cream` 的家园待机图沿用当前家园小狗素材，作为商店预览和后续资源制作的基础。
- 未制作完成的动作可以先使用静态待机图或简单方块占位素材补齐资源映射，等正式图片上传后直接替换。
- 缺少某动作时，运行时优先回退到当前宠物自己的静态待机图；不会借用另一只宠物的动作，也不会因为缺图阻止启动。
- 商店只显示宠物主预览图和拥有/购买/使用状态，不新增复杂的动作预览槽位。

资源目录建议保持宠物边界清晰：

```text
assets/runtime/pets/
├── manifest.json
├── desktop/       午餐肉等桌面资源
├── home/          已制作的家园资源
└── placeholders/  尚未完成动作的临时占位素材
```

制作源图继续放入 `assets/source`，不会进入 Windows 或 macOS 安装包。

## 5. 商店与切换

现有商店顶部新增栏目，名称固定为：

```text
🐶 宠物
```

宠物卡片显示：

- 待机预览图。
- 当前昵称。
- `已拥有`、`使用中` 或购买价格。
- 一个明确的购买或切换操作。

首期商店内容：

| 宠物 | 初始名字 | 首期状态 | 预览 |
|---|---|---|---|
| 午餐肉 | 午餐肉 | 默认拥有、默认使用 | 当前桌面待机图 |
| 冰淇淋 | 冰淇淋 | 显示但未拥有，原价 1000 Pet币，76 折后 760 Pet币 | 当前家园待机图 |

购买宠物成功后自动切换到该宠物。点击已拥有宠物的切换按钮后，更新 `active_pet_id`，保存状态，并让桌面和家园立即刷新到该宠物的待机资源。改名入口只修改当前宠物的昵称。

宠物购买/切换与套装购买/装备保持独立：宠物是角色身份，套装是角色外观资源。未来若某套装没有当前宠物对应的动画，则使用当前宠物自己的待机图回退。

## 6. 渲染与行为

桌面和家园都通过同一套“当前宠物资源解析”接口取得资源：

```text
active_pet_id
  → pet registry
  → current pet profile
  → scene-specific animation lookup
  → current pet idle fallback
  → renderer
```

- 当前宠物切换后，两个场景清理正在播放的旧动作并回到当前宠物待机。
- 互动、睡觉、挖宝、玩耍等状态继续沿用现有状态机；只替换资源来源。
- 缺少动作资源时使用当前宠物待机图，不显示其他宠物的形象。
- 当前宠物昵称同步到成长卡、说话气泡、聊天人格、教程命名和商店卡片。
- 当前宠物的桌面坐标和家园坐标独立保存，切换后回到该宠物上次在对应场景的位置；首次使用新宠物时使用安全默认位置。

## 7. 测试与验收

实现时先为以下行为增加回归测试：

- 新存档默认拥有并激活午餐肉。
- 旧存档数据迁移到午餐肉且迁移幂等。
- 等级、经验、Pet币、家具和玩家进度在宠物切换前后保持不变。
- 午餐肉和冰淇淋的属性、好感、昵称、位置和聊天记忆互不串写。
- 桌面和家园读取同一个 `active_pet_id` 并同步刷新。
- 商店正确显示午餐肉和冰淇淋的预览、拥有和切换状态。
- 缺少动作资源时回退到当前宠物静态待机图。
- 临时方块或待机占位资源不会造成启动崩溃。
- 现有装扮、家居、小游戏、聊天和更新逻辑不回归。

验收标准：首次启动桌面和家园都显示午餐肉；商店显示“宠物”栏目和冰淇淋卡片；切换后两个场景同时显示冰淇淋；等级、Pet币和家具保持不变，而属性、好感和聊天记忆按宠物分别保存。

## 8. 后续资源补齐顺序

1. 先确认午餐肉在桌面与家园的待机图、尺寸和锚点统一。
2. 上传冰淇淋正式待机图，替换当前家园待机预览。
3. 按宠物逐步补齐行走、睡觉、喂食、抚摸、玩耍和挖宝动画。
4. 每次补资源只更新注册表和运行资源，并运行缺图回退、资源路径和 GUI 相关测试。
