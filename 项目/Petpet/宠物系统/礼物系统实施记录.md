## 2. 实施要点与坑位

- **`give_gift` 门面回退**：测试裸 state 无 `active_pet_id` 时送 `lunch_meat` 被判"没有这只宠物"——旧扁平存档（无 `pets` 字典）门面即唯一宠物，`give_gift` 增加 `not isinstance(pets, dict)` 分支直接走门面加点。
- **`add_affection` 重构零行为变更**：records 落账留在 `add_affection`，`_apply_affection` 只动加点+升级，非当前宠物的 records（`affection_earned/level_ups`）在 `give_gift` 共享层补记——先跑全量旧测试确认无回归再动 UI。
- **测试裸 state 的币要落玩家层**：截图脚本里手改门面 `pet_coins` 不进 `player` 字典，`_coin_balance` 读 player 显示 0、购买键禁用——脚本内改为购买前直接设值即可（真实链路 `add_coins` 双端同步无此问题）。
- **Git Bash 吞 PowerShell `$_`**：内联 `powershell -Command "...$_..."` 被展开成 bash 路径——重启脚本一律落 `Temp\*.ps1` 再 `-File` 执行。
- **重启验证假阳性（本轮真实事故）**：`Stop-Process` 击杀循环按 `Name+CommandLine` 过滤**静默未命中**用户已在跑的旧实例（无 killing 输出＝没杀任何东西）；随后新起实例被单实例召回顶掉退出；复查 `Get-CimInstance` 按名字反查把**旧进程**当成"新宠物"报告 RESTART_OK。三层错误叠成假验证。铁律：**重启验证必须追踪自己启动的那个 PID（`Start-Process -PassThru`），绝不用名字反查结果当自己的实例**；击杀循环为空时（无 killing 输出）要当作异常排查而不是跳过。
- **PS1 里 backtick 续行 + CRLF 会让整个脚本解析炸裂**（here-string 内容被当 PowerShell 解析）——`Start-Process` 等长命令写单行。
- **面板第三分栏零新布局逻辑**：`TAB_SLOTS` 加条目后既有循环自动三键紧连；`_show_tab` 的 pages 字典补一项即可。
