# 礼物系统设计

> [!summary] Summary
> 礼物是可重复购买的消耗品：在商店第 5 页「礼物」用 Pet 币买入共享背包，再到宠物详情面板第 3 分栏「礼物」送给当前选中宠物换取好感度。本文记录目录数值、存档字段、好感落账路径与交互决策（2026-09-07 实施落地）。

## 1. 目标与定位

- 补一条「Pet 币 → 好感度」的主动兑换通道：现有好感来源是互动冷却（抚摸/喂食/玩耍等，见 `AFFECTION_ACTION_GAINS`）与被动陪伴，礼物让玩家能集中表达心意。
- 送礼入口在宠物详情面板（用户指定的第三个分栏），购买入口在商店（用户指定的第 5 页）；两端共享玩家级背包。

## 2. 礼物目录（三档 × 每档三选一）

定义在 `petpet/progression/core.py::GIFT_DEFINITIONS`（带 `tier` 字段），档位表 `GIFT_TIER_META`：

| 档位 | 标签 | 价格 | 基础好感 | 礼物（id） |
|---|---|---|---|---|
| 1 | 小小心意 | 80 | +10 | 甜心曲奇 `sweet_cookie` / 元气布丁 `milk_pudding` / 香香起司 `cheese_cubes` |
| 2 | 真挚款待 | 200 | +30 | 肉肉罐头 `meat_can` / 毛绒小球 `plush_ball` / 莓莓小篮 `berry_basket` |
| 3 | 豪华大礼 | 480 | +80 | 爱心礼盒 `love_box` / 暖暖小毯 `warm_blanket` / 亮晶晶奖牌 `shiny_medal` |

数值标定：好感曲线 `affection_to_next(level) = min(200, 20 + level*10)`，早期 30/级——大礼盒约抵 2~3 级早期好感，与互动冷却收益相比明显更贵但可自由支配，符合"攒币表达心意"的定位。

**中性化原则（用户定稿 2026-09-07 偏好轮）**：礼物名目与图标不得带犬类（或猫类）专属意象——不用骨头/毛线球/小鱼干/狗狗等词，测试 `test_no_dog_specific_naming` 守卫；这样后续加入小猫等新宠物时目录无需改动，只需在注册表为新宠物声明偏好。初版目录（骨头饼干等 3 项）已整体下架，存量骨头饼干在 `ensure_progression` 中一次性折算为同档甜心曲奇（库存迁移，玩家资产不蒸发）。

## 3. 数据模型

| 层 | 字段 | 说明 |
|---|---|---|
| 玩家共享 | `gift_inventory: dict[gift_id, count]` | `state.PLAYER_FIELDS` 新增，schema v3→v4；`ensure_progression` 归一化（未知 ID 剔除、负数清零、0 值不落盘、骨头饼干存量迁移） |
| 玩家 records | `gifts_bought` / `gifts_given` | `RECORD_DEFAULTS` 新增计数器，供日后成就/记录页扩展 |
| 宠物注册表 | `gift_preferences: [gift_id × 3]` | `pets/manifest.json` 每宠一条，按档位 1→3 排列，每档恰好一个最爱；新宠物（小猫等）入表时自带偏好 |
| 好感 | 复用 `affection_points` / `affection_level` | 每宠物独立，无新增字段 |

当前偏好（与宠物性格对齐，可在注册表随时调）：

| 宠物 | 档一最爱 | 档二最爱 | 档三最爱 | 主题 |
|---|---|---|---|---|
| 午餐肉（元气陪伴犬） | 甜心曲奇 | 肉肉罐头 | 爱心礼盒 | 吃货热情线 |
| 冰淇淋（温柔家园犬） | 元气布丁 | 莓莓小篮 | 暖暖小毯 | 甜系治愈线 |

## 4. 核心函数（progression/core.py）

- `purchase_gift(state, gift_id)`：币不足拒绝；成功扣共享币（`_shared_pet_coins` 双端同步）、库存 +1、records 落账。返回 `{ok, price, count, message}` 与其他 purchase_* 同形。
- `preferred_gift_ids(pet_id)`：读注册表偏好（过滤未知 ID；未声明返回空）。
- `gift_affection_for(pet_id, gift_id)` → `(基础, 实得, 是否最爱)`：最爱好感 ×1.5 取整（10→15 / 30→45 / 80→120）。
- `give_gift(state, pet_id, gift_id)`：库存校验 → 偏好加成计算 → 好感落账 → 库存 -1（清零删键）。好感落账分两路：
  - **当前宠物**：走门面 `add_affection`（升级循环 + records 由其落账）；
  - **其他宠物**：直接在该宠物 `pets[pet_id]` profile 上跑 `_apply_affection`（从 `add_affection` 抽出的加点+升级纯函数），records 在共享层补记。
  - 旧扁平存档（无 `pets` 字典）门面即唯一宠物，直接走门面路径。偏好对两路同样生效。

## 5. 交互设计

| 端 | 内容 |
|---|---|
| 商店第 5 页「礼物」 | 页签追加在「强化」之后；**三档分组展示**（档头：`小小心意 · 80 Pet币 · 好感 +10` 式一行琥珀小字），每档 3 卡 = 宠物卡同款横版（图标/名称/描述/价格签/持有数/购买键）。**当前宠物的最爱卡带「♥ 最爱」红标 + 「TA的最爱！好感 +15」**（换当前宠物后随注册表刷新）；消耗品可无限复购，购买直购无弹窗，余额不足购买键禁用 |
| 面板第 3 分栏「礼物」 | `TAB_SLOTS` 追加「礼物」（素材 `tab_gift.png`，三键紧连排布沿用既有循环）；页内只展示背包有货的礼物卡（虚线暖框、图标、好感+数量、`_ArtButton` 送出键）；最爱卡名称旁「♥ 最爱」红标 + 好感行珊瑚色 `♥ 好感 +15`（普通卡琥珀色 `好感 +10`）；空背包显示引导文案指向商店 |
| 送礼确认 | 复用商店 `PurchasePopup`，扩展 `confirm_text/cancel_text` 参数成双键（默认参数行为不变）；好感行随偏好显示 `好感 +15（TA的最爱！）`；确认后扣库存、加好感、存档、小狗气泡反馈（最爱时「TA 超喜欢！」）、待机区飘 5 颗心、面板刷新 |
| 好感刷新 | 简介页好感行/进度数值随面板 `refresh()` 重取快照自动更新 |

## 6. 决策记录

- **偏好机制（用户定稿 2026-09-07 偏好轮）**：每只宠物每档一个最爱（共 3 个），最爱礼好感 ×1.5 取整（15/45/120）；偏好声明在宠物注册表而非写死在礼物定义——新宠物入表即自带偏好，目录保持全局一份。
- **中性化目录（用户定稿）**：礼物不绑定犬类意象，为小猫等后续宠物留位；名目用食物/玩具/物件三类通用意象，守卫测试禁止骨头/毛线/鱼干/狗狗字样。
- **无冷却无上限**：Pet 币本身稀缺（成就/挖宝/小游戏产出），是天然门槛；不接入 `grant_interaction_affection` 冷却体系。
- **消耗品而非永久**：礼物语义即"送出即消耗"；库存 0 的礼物不显示卡（而非置灰），页面保持轻量。
- **占位素材策略**：9 枚图标/页签图标/送出键/第三分栏均为 `tools/generate_gift_assets.py` 程序生成的暖色占位稿；`tab_gift.png` 以 `tab_intro.png` 为底逐行修复文字区再写「礼物」（幼圆 SIMYOU.TTF），保证与既有两枚分栏边框/渐变/字体零偏差。正式素材到位后同名替换即可，生成脚本保留为重建依据。
- **旧库存迁移**：`ensure_progression` 把存量 `bone_cookie` 一次性折算为同档 `sweet_cookie`（同价同好感），中性化改版不吞玩家资产。
- **套装页签图标语义遗留**：商店「套装」页签现用 `gift_icon.png`（历史命名），礼物页签用新生成的 `gift_tab_icon.png`，二者并存不冲突；若用户要求语义归位再换。
- **面板只送当前宠物**：面板 rail 切换卡即切换 active 宠物，故送礼目标恒为 active（`give_gift` 仍支持显式 pet_id，为多宠并存留 API）。
