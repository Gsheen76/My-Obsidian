# 礼物系统设计

> [!summary] Summary
> 礼物是可重复购买的消耗品：在商店第 5 页「礼物」用 Pet 币买入共享背包，再到宠物详情面板第 3 分栏「礼物」送给当前选中宠物换取好感度。本文记录目录数值、存档字段、好感落账路径与交互决策（2026-09-07 实施落地）。

## 1. 目标与定位

- 补一条「Pet 币 → 好感度」的主动兑换通道：现有好感来源是互动冷却（抚摸/喂食/玩耍等，见 `AFFECTION_ACTION_GAINS`）与被动陪伴，礼物让玩家能集中表达心意。
- 送礼入口在宠物详情面板（用户指定的第三个分栏），购买入口在商店（用户指定的第 5 页）；两端共享玩家级背包。

## 2. 礼物目录（三档）

定义在 `petpet/progression/core.py::GIFT_DEFINITIONS`，顺序即商店/面板展示顺序：

| ID | 名称 | 价格（Pet币） | 好感 | 图标（assets/runtime/ui/gifts/） |
|---|---|---|---|---|
| `bone_cookie` | 骨头饼干 | 80 | +10 | `bone_cookie.png` |
| `meat_can` | 肉肉罐头 | 200 | +30 | `meat_can.png` |
| `love_box` | 爱心礼盒 | 480 | +80 | `love_box.png` |

数值标定：好感曲线 `affection_to_next(level) = min(200, 20 + level*10)`，早期 30/级——大礼盒约抵 2~3 级早期好感，与互动冷却收益相比明显更贵但可自由支配，符合"攒币表达心意"的定位。

## 3. 数据模型

| 层 | 字段 | 说明 |
|---|---|---|
| 玩家共享 | `gift_inventory: dict[gift_id, count]` | `state.PLAYER_FIELDS` 新增，schema v3→v4；`ensure_progression` 归一化（未知 ID 剔除、负数清零、0 值不落盘） |
| 玩家 records | `gifts_bought` / `gifts_given` | `RECORD_DEFAULTS` 新增计数器，供日后成就/记录页扩展 |
| 好感 | 复用 `affection_points` / `affection_level` | 每宠物独立，无新增字段 |

## 4. 核心函数（progression/core.py）

- `purchase_gift(state, gift_id)`：币不足拒绝；成功扣共享币（`_shared_pet_coins` 双端同步）、库存 +1、records 落账。返回 `{ok, price, count, message}` 与其他 purchase_* 同形。
- `give_gift(state, pet_id, gift_id)`：库存校验 → 好感落账 → 库存 -1（清零删键）。好感落账分两路：
  - **当前宠物**：走门面 `add_affection`（升级循环 + records 由其落账）；
  - **其他宠物**：直接在该宠物 `pets[pet_id]` profile 上跑 `_apply_affection`（从 `add_affection` 抽出的加点+升级纯函数），records 在共享层补记。
  - 旧扁平存档（无 `pets` 字典）门面即唯一宠物，直接走门面路径。

## 5. 交互设计

| 端 | 内容 |
|---|---|
| 商店第 5 页「礼物」 | 页签追加在「强化」之后（`page_ids` 与页签栏同步 +1）；卡片 = 宠物卡同款横版（图标/名称/描述/好感加成/价格签/持有数/购买键）。消耗品可无限复购，购买走 `_finish` 型直购（无弹窗），余额不足购买键禁用 |
| 面板第 3 分栏「礼物」 | `TAB_SLOTS` 追加「礼物」（素材 `tab_gift.png`，三键紧连排布沿用既有循环）；页内只展示背包有货的礼物卡（虚线暖框、图标、好感+数量、`_ArtButton` 送出键）；空背包显示引导文案指向商店 |
| 送礼确认 | 复用商店 `PurchasePopup`，扩展 `confirm_text/cancel_text` 参数成双键（默认参数行为不变）；确认后扣库存、加好感、存档、小狗气泡反馈、待机区飘 5 颗心（QVariantAnimation 抬升+淡出）、面板刷新 |
| 好感刷新 | 简介页好感行/进度数值随面板 `refresh()` 重取快照自动更新 |

## 6. 决策记录

- **无冷却无上限**：Pet 币本身稀缺（成就/挖宝/小游戏产出），是天然门槛；不接入 `grant_interaction_affection` 冷却体系。用户问卷未答，按推荐项实施，可在反馈轮推翻。
- **消耗品而非永久**：礼物语义即"送出即消耗"；库存 0 的礼物不显示卡（而非置灰），页面保持轻量。
- **占位素材策略**：三图标/页签图标/送出键/第三分栏均为 `tools/generate_gift_assets.py` 程序生成的暖色占位稿；`tab_gift.png` 以 `tab_intro.png` 为底逐行修复文字区再写「礼物」（幼圆 SIMYOU.TTF），保证与既有两枚分栏边框/渐变/字体零偏差。正式素材到位后同名替换即可，生成脚本保留为重建依据。
- **套装页签图标语义遗留**：商店「套装」页签现用 `gift_icon.png`（历史命名），礼物页签用新生成的 `gift_tab_icon.png`，二者并存不冲突；若用户要求语义归位再换。
- **面板只送当前宠物**：面板 rail 切换卡即切换 active 宠物，故送礼目标恒为 active（`give_gift` 仍支持显式 pet_id，为多宠并存留 API）。

## 7. 验证口径

offscreen 全量 pytest（含新 `tests/test_gift_system.py` 19 条：目录/库存/购买/送出/存档投影/UI 三端）→ Windows 真实平台截图（商店礼物页、面板礼物分栏、确认弹窗）→ 精确重启 EnumWindows 验证可见。四步齐备才算完成（AGENTS.md 核心原则）。
