> [!success] 已完成的程序能力
> Petpet 已能按个人 Key 是否存在自动选择聊天路径：有 Key 时直连 `GLM-4.6V-Flash` 并支持图文；无 Key 时在玩家首次明确同意后，经默认代理使用 `deepseek-v4-flash-free` 进行纯文字聊天。

## 客户端行为

- 无个人 Key：显示“免费聊天 · DeepSeek V4 Flash”，隐藏图片上传。
- 首次免费聊天：说明消息会交给限时免费模型处理，且免费期内容可能用于模型改进；拒绝后不会发送、不会增加聊天记录。
- 有个人 Key：自动切换到 `GLM-4.6V-Flash`，文字和单图消息都直接请求智谱接口。
- 移除 Key：自动回到默认免费文字模式。
- 历史 `GLM-4-Flash` / `GLM-4.7-Flash` 配置会按 Key 是否存在自动迁移。
- 默认额度耗尽或代理不可用：显示中性的系统提示，立即恢复输入框，不写入小狗回答，也不弹出阻塞式 Key 对话框。
- 默认公开代理地址既可保存在用户配置，也可由发布包的 `config.json.example` 提供；用户已有配置缺少该字段时仍能读取发布默认值。

## Worker 边界

- 目录：`cloudflare-worker/`
- 入口：`POST /v1/chat`
- 只接受 UUID v4 安装 ID和纯文字消息；最多 7 条消息、每条最多 1200 字符、请求正文最多 16 KiB。
- 系统提示始终保留，并只携带最近上下文，总消息数不超过 7。
- 安装 ID 与来源 IP 分别限制为 20 次/UTC 日；KV 中只保存散列后的日期计数键。
- 上游改为 OpenRouter 兼容接口 `https://openrouter.ai/api/v1/chat/completions`，默认模型为免费路由 `openrouter/free`；它会从当前可用免费模型中自动选择，每次最多 200 个输出 token，并关闭 thinking。
- Worker 缺少 Secret/KV、上游异常或额度耗尽时，只返回稳定错误码。

> [!warning] 部署状态
> Cloudflare Worker、KV 和公开地址已经创建：`https://petpet-default-chat.gsheen-petpet.workers.dev/v1/chat`。上游正在从 OpenCode 切换到 OpenRouter；必须使用全新的 `OPENROUTER_API_KEY` Worker Secret，确认线上请求成功后删除旧 `OPENCODE_API_KEY` Secret。真实 Key 不能放入仓库、发布包、Obsidian 或日志。

## 发布前操作

1. 项目所有者创建 Cloudflare KV，并把命名空间 ID 写入 `wrangler.toml`。
2. 用一枚新 OpenRouter Key 执行 `wrangler secret put OPENROUTER_API_KEY`。
3. 部署 Worker；公开 HTTPS `/v1/chat` 地址已写入发布用 `config.json.example`。
4. 重新执行 Worker 测试、客户端 focused tests、全量 `pytest -q`、编译检查与敏感信息检查。

## 维护规则

- `openrouter/free` 是免费路由；模型池和限流会变化。若需要固定模型，可将一个当前可用的 `:free` 模型 ID 写入 Worker 的 `OPENROUTER_MODEL` 环境变量。
- 每次新增或调整玩家可见玩法时，继续同步维护 `assets/knowledge/game_knowledge.json`，让小狗能回答当前版本内容。
- 不在任何项目 Markdown 中记录 Secret 值，只记录变量名和轮换步骤。

## 2026-08-12 聊天模式与容量更新

- 聊天模式改为玩家显式选择“免费聊天”或“自己配置 API”，不再根据本机是否保存 Key 自动切换。
- 免费模式即使检测到已保存 Key，也只调用项目方 OpenRouter 免费代理；后台用户画像更新同样不会调用个人 Key。
- 切换回免费模式会保留本机 Key，之后重新选择自配模式时可以继续使用。
- 自配弹窗统一包含个人模型选择与 API Key 输入；当前个人模型为 `GLM-4.6V-Flash`。
- Worker 系统提示上限提升为 4000 字符；用户与助手消息保持每条 1200 字符；总请求仍限制为 16 KiB。
- 客户端会按角色裁剪内容，超出总大小时优先移除最旧历史，再以 UTF-8 字节预算裁剪系统提示。

### 免费聊天空响应修复

- 线上复现发现 `openrouter/free` 随机选中 Nemotron 推理模型时，旧的智谱字段 `thinking.type=disabled` 会被忽略。
- 模型把 200 个输出 token 全部用于 `reasoning`，没有产生 `delta.content`，客户端因此得到 `default_provider_unavailable`。
- Worker 已改用 OpenRouter 官方参数 `reasoning.effort=none`，并以契约测试禁止旧 `thinking` 字段再次出现。
- 客户端短历史选择曾使用 `[第一条, *最后六条]`，无历史时会把同一份系统提示发送两次；现改为从第二条开始截取最近六条，确保系统提示唯一。
- 新增 `chat_diagnostic.log` 元数据诊断日志，只记录时间、请求阶段、HTTP 状态、异常类型、正文/推理字符数与结束标记；绝不记录消息正文、回复正文或任何 Key。

### Windows 代理链路修复

- 实际操作与隔离诊断确认：Python `urllib` 在当前 Windows 代理环境中无论使用环境代理还是直连都会触发 `TimeoutError`，而 `requests` 使用同一网络环境可在约 7 秒内返回 HTTP 200。
- 默认免费代理传输已迁移到 `requests.post(..., stream=True)`；个人智谱请求保持原实现，避免扩大变更范围。
- `requests>=2.31,<3` 已加入运行与构建依赖，保证源码版和发布包行为一致。
- 教程与 README 同步纠正：双击进入小屋，聊天入口是右键快捷菜单中的“聊天”。

### 2026-08-13 免费模型首字超时兜底

> [!bug] 根因
> 线上无隐私测速中，`openrouter/free` 实际分配到 `nvidia/nemotron-nano-9b-v2:free`（Nvidia）。Worker 在 1.73 秒收到响应头，但直到 7.08 秒才出现首个有效文字，7.84 秒才结束。旧逻辑只在 OpenRouter 返回错误时切换 GLM，因此“HTTP 200 但迟迟不出字”不会触发兜底。

- Worker 现在等待 OpenRouter 的首个有效 `delta.content`，心跳注释不算正文。
- 5 秒内没有有效文字时，立即取消该慢流并改用智谱官方 `glm-4.7-flash`；正常快速模型仍直接流式返回。
- 客户端诊断日志新增实际 `model`、`provider`、`first_content_ms` 与 `total_ms`，仍不记录问题、回答或 Key。
- 修复后线上测速由 `cohere/north-mini-code:free`（Cohere）响应，1.66 秒出现首字，3.49 秒完成。
- Worker 部署版本：`80c45a7e-3980-43ed-828c-ee7e685809c4`。
