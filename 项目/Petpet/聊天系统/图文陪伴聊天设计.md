# 图文陪伴聊天设计

> [!info] 项目内规格
> `docs/superpowers/specs/2026-08-11-multimodal-chat-design.md`

## 已确认范围

- 聊天模型替换为 `GLM-4.7-Flash`（文本）与 `GLM-4.6V-Flash`（图文）。
- 仅视觉模型显示上传入口；每次消息支持一张 PNG、JPG/JPEG 或 WEBP 图片。
- 上传后在输入区显示可移除预览，发送后的聊天历史保留缩略图。

## 本地数据与隐私

> [!important] 不保存原图或 Base64
> 原图只用于当次智谱 API 请求；本地仅保留 320 px 缩略图。聊天记忆记录缩略图相对路径和文件名，不含原图路径、图片字节或 Base64。

- 图片限制为 10 MiB。
- `GLM-4.7-Flash` 不接收图片；切回它时清除尚未发送的图片。
- 图文模型的后续纯文本消息不会自动再次上传旧图。
- 清除记忆同时删除由 Petpet 管理的聊天缩略图。
- 智谱流式响应如果只有结束标记而没有正文，会走离线回复，避免出现只有小狗图标的空白气泡。
- `GLM-4.7` 默认会输出思考内容；Petpet 的陪伴聊天明确关闭思考，以避免 200-token 短回复预算被推理过程消耗。
- `rate_limit`、`empty_response` 会显示为自然的小狗提示，不显示内部错误码。

## 接口依据

智谱官方的 `GLM-4.6V-Flash` 文档说明，该模型支持用一条消息中的 `image_url` 和 `text` 内容块传入图片与文字，本地图片使用原始 Base64 字符串；接口仍为 `POST /api/paas/v4/chat/completions`。 [官方文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)

## 空白回复修复（2026-08-11）

截图验证发现，`GLM-4.7-Flash` 偶尔会返回没有 `delta.content` 的流结束标记；此前 Petpet 误将它保存为空的成功回复。现已改为发出 `empty_response`，由既有离线回复接管。

- 回归 RED：`('done', '')`，符合问题复现。
- Focused AI/聊天测试：21 passed in 0.71s。
- 最终全量：314 passed in 73.95s。

## GLM-4.7 正文耗尽修复（2026-08-11）

实测流式接口先返回大量 `reasoning_content`，短回复请求会在可见正文开始前触发 `finish_reason: length`。现有请求已加：

```json
"thinking": {"type": "disabled"}
```

一条不含私人内容的真实验证请求随后收到 46 个字符的正文。最终全量：315 passed in 37.56s。
