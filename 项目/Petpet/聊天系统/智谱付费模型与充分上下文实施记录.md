# 智谱付费模型与充分上下文实施记录

> [!success] 已完成
> 阿里云大陆聊天入口已改用 `glm-4.7-flashx`，桌面端、阿里云和 Cloudflare 的公开输入契约已统一；本轮只生成本地上传包，尚未部署线上函数。

## 模型与成本控制

- 阿里云默认模型：`glm-4.7-flashx`；`ZHIPU_MODEL` 环境变量仍可覆盖。
- 最大输出保持 200 Tokens，思考模式保持关闭。
- 玩家自行配置的 `GLM-4.6V-Flash` 图文聊天不变。
- 智谱非成功响应只记录 HTTP 状态、耗时和安全的数值业务错误码，不记录聊天内容、上游错误说明或 API Key。

## 上下文契约

- 请求体最多 32768 字节；
- 系统消息最多 8000 字符；
- 用户与助手单条消息最多 1600 字符；
- 每次最多 12 条消息；
- 实际发送最近 10 条历史消息和当前问题；
- 人设提示词保留主人长期资料、时间、情绪提示和按需知识，不再重复嵌入近期聊天记录。

## 按需游戏知识

- 新增“Petpet 游戏概览”，覆盖桌面陪伴、小屋、三项状态、经验与好感、Pet币、家具装修、小游戏、宝藏、设置和聊天。
- 游戏问题最多注入 5 条相关资料；宽泛的游戏介绍问题优先命中总览。
- 普通问候、上班、情绪和日常陪伴聊天不会注入 `# 游戏资料`。
- 具体小游戏名称优先命中对应玩法，不会被宽泛总览抢占。

## 首次线上部署验证

2026-08-14 上传后进行无隐私冒烟请求，函数实例未能启动。平台实际使用了 `node server.js`，而部署包入口是 `src/server.js`，日志明确返回 `MODULE_NOT_FOUND: /code/server.js`。这不是模型、Key 或请求契约错误。

修复方式：在函数“配置 → 基础配置”中把启动命令设为 `node src/server.js`（或命令 `node`、参数 `src/server.js`），监听端口保持 `9000`，保存并部署配置后重新验证；不需要重新制作 ZIP。

第二次线上验证确认阿里云自定义运行时不会从 `PATH` 查找 `node`，返回 `CAFileNotFound: the file node is not exist`。由于函数已挂载官方 Node.js 20 层，最终启动命令应使用绝对路径：`/var/fc/lang/nodejs20/bin/node src/server.js`。

第三次验证中启动命令已正确执行，但线上返回 `MODULE_NOT_FOUND: /code/src/server.js`。重新核对本地 ZIP，确认其根目录确实只有 `package.json` 和 `src/server.js`，SHA-256 仍为 `281E7641BFB5B63AAADB8715B11483AF62F6673ABED7B2719A9E092BD0CA7BBD`。因此故障边界位于阿里云代码上传/部署：当前 LATEST 版本没有实际采用该 ZIP。需要在“代码”页重新上传此 ZIP，确认文件树出现 `src/server.js`，并点击“部署代码”，不能只部署配置。

重新上传并部署代码后，第四次无隐私冒烟已返回 `200 text/event-stream`，包含 `[DONE]`，总耗时约 3.37 秒，证明函数与 SSE 链路恢复。但响应元数据仍显示 `glm-4.7-flash`，说明线上环境变量 `ZHIPU_MODEL=glm-4.7-flash` 覆盖了代码默认值。需将其改为 `glm-4.7-flashx` 或删除该变量后再次部署配置。

将环境变量更新为 `ZHIPU_MODEL=glm-4.7-flashx` 并部署配置后，最终无隐私冒烟验证通过：`200 text/event-stream`、完整 `[DONE]`、响应模型 `glm-4.7-flashx`，总耗时约 4.08 秒。阿里云大陆聊天入口至此正式在线。

## 玩家实际体验日志

2026-08-14 17:14 的连续两次实际聊天均返回 `zhipu_response status=200`，上游响应头耗时分别为 546ms 和 548ms，波动仅 2ms；没有 429、5xx、启动异常或配置错误。`FC Invoke End` 早于自定义日志一秒显示属于平台日志采集与标准输出刷新顺序，不代表函数提前中断。当前 `elapsedMs` 衡量的是智谱返回 HTTP/SSE 响应头的时间，不是整段流式正文完全生成的总时间。
