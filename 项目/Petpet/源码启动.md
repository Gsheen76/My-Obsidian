# 源码启动

> [!summary] Summary
> Petpet 当前真实源码位于 `D:\Agent_project\Petpet`，统一从根目录 `pet.py` 启动。旧的 `.worktrees\home-scene-system` 不再作为启动或修改来源。

## 当前源码入口

源码统一从以下项目根目录的 `pet.py` 启动：

```text
D:\Agent_project\Petpet
D:\Agent_project\Petpet\pet.py
```

> [!warning] 不要再从旧工作树启动
> `D:\Agent_project\Petpet\.worktrees\home-scene-system` 是历史开发工作树。当前功能、宠物资源、商店修改和右键菜单修复均已合入根目录 `main`，继续启动旧工作树会看到过期行为。

## 运行环境

当前源码已使用以下环境验证：

- Python `3.12`（当前机器使用 Anaconda base 环境）
- PyQt5 `5.15.2`
- `requests >= 2.31, < 3`

先确认终端实际使用的解释器：

```powershell
python --version
(Get-Command python.exe).Source
(Get-Command pythonw.exe).Source
```

当前仓库没有强制要求 `.venv`。日常可直接使用已经安装依赖的 Python 环境：

```powershell
Set-Location "D:\Agent_project\Petpet"
python -m pip install -r requirements\runtime.txt
```

如需建立独立环境，可执行：

```powershell
Set-Location "D:\Agent_project\Petpet"
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements\runtime.txt
```

## 前台启动

调试、验证功能或查看报错时使用前台启动：

```powershell
Set-Location "D:\Agent_project\Petpet"
python pet.py
```

前台启动适合查看 Python traceback、Qt 警告和启动路径。需要停止时按 `Ctrl+C`。

## 后台启动

确认前台运行正常后，可使用 `pythonw.exe` 隐藏命令行窗口：

```powershell
Set-Location "D:\Agent_project\Petpet"
$petPath = (Resolve-Path -LiteralPath ".\pet.py").Path
$pythonw = (Get-Command pythonw.exe -ErrorAction Stop).Source
Start-Process -FilePath $pythonw `
    -ArgumentList ('"' + $petPath + '"') `
    -WorkingDirectory (Get-Location) `
    -WindowStyle Hidden
```

退出源码版 Petpet 时，从系统托盘右键选择“退出”。

## 确认正在运行正确源码

使用完整 `pet.py` 路径筛选进程，避免把其他 Python 程序误认为 Petpet：

```powershell
$petPath = (Resolve-Path -LiteralPath "D:\Agent_project\Petpet\pet.py").Path
Get-CimInstance Win32_Process |
    Where-Object {
        $_.Name -match '^python(w)?\.exe$' -and
        $_.CommandLine -like "*$petPath*"
    } |
    Select-Object ProcessId, Name, CommandLine
```

正常后台启动时应看到一条 `pythonw.exe` 记录，命令行中包含：

```text
D:\Agent_project\Petpet\pet.py
```

## 修改源码后安全重启

优先从托盘退出旧小狗，再重新执行后台启动命令。如果旧进程没有响应，可只终止命令行精确包含当前源码入口的进程：

```powershell
$projectRoot = (Resolve-Path -LiteralPath "D:\Agent_project\Petpet").Path
$petPath = (Resolve-Path -LiteralPath "$projectRoot\pet.py").Path

$oldProcesses = @(
    Get-CimInstance Win32_Process |
        Where-Object {
            $_.Name -match '^python(w)?\.exe$' -and
            $_.CommandLine -like "*$petPath*"
        }
)

foreach ($process in $oldProcesses) {
    Stop-Process -Id $process.ProcessId -Force
}

$pythonw = (Get-Command pythonw.exe -ErrorAction Stop).Source
Start-Process -FilePath $pythonw `
    -ArgumentList ('"' + $petPath + '"') `
    -WorkingDirectory $projectRoot `
    -WindowStyle Hidden
```

> [!important] 进程范围
> 不要按名称批量结束所有 `python.exe` 或 `pythonw.exe`。必须同时匹配完整 `D:\Agent_project\Petpet\pet.py` 路径，避免关闭其他 Python 程序。

## 常见问题

### 重复执行后没有第二只小狗

Petpet 使用单实例机制。已有实例运行时，再次执行 `python pet.py` 不会创建第二只小狗，而会尝试唤醒现有实例。修改代码后应先退出旧进程再启动。

### 小狗启动后立即退出

先使用前台方式运行 `python pet.py` 查看 traceback。如果没有 Python traceback，而 Windows 事件查看器显示 `Qt5Core_conda.dll`，应记录异常代码和发生操作；右键快速双击导致的 `0xc0000005` 已在提交 `ee6b4e1` 修复，详见 [[开发记录/2026-08-21 右键快速双击闪退修复]]。
