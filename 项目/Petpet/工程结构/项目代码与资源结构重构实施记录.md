# 项目代码与资源结构重构实施记录

## 第一阶段：包骨架与统一路径

本阶段已经建立 `petpet` Python 包，并将路径与旧数据迁移实现收拢到 `petpet.app.paths`。

- 根目录 `pet.py` 保持不变，仍是源码和打包入口。
- 根目录 `app_paths.py` 现在是显式兼容转发层，现有模块无需同步修改导入。
- `petpet.app.paths.SOURCE_DIR` 仍解析为当前 worktree 根目录，不会因模块进入子目录而错误指向 `petpet/`。
- 旧数据目录查找、缺失文件复制、默认配置种子与资源目录常量保持原行为。
- 本阶段未修改版本号、发布脚本、远端分支或发布资产。

- focused tests：`tests/test_app_paths.py` 共 `4 passed`。
- 导入检查：`app_paths`、`petpet.app.paths` 和 `pet` 均可导入，`SOURCE_DIR` 指向当前 worktree。
- 全量测试：`458 passed in 26.96s`。
- `git diff --check`：无空白错误。

## 第二阶段：玩家与双宠物存档基础

新增 `petpet.app.state`，并接入现有 `pet.load_state()` / `pet.save_state()`：

- `player` 保存共享的等级、经验、Pet币、成就、记录、强化、已拥有装扮、家园库存与教程状态。
- `pets.desktop` 和 `pets.home` 分别保存名字、饱腹、心情、精力、好感、互动冷却、睡眠/位置与已装备外观。
- 旧单宠物存档首次加载时深拷贝为两份宠物资料，嵌套列表和字典不共享引用。
- 迁移函数可重复调用；已修改的 `pets.home` 不会被顶层桌面兼容字段覆盖。
- 迁移期间，旧代码继续使用顶层字段；加载时由嵌套桌面资料填充，保存时只同步回 `pets.desktop`，不会覆盖 `pets.home`。
- 聊天记忆仍在聊天阶段拆分；家园 UI 也将在家园阶段开始直接使用 `pets.home`。

### 测试证据

- 纯迁移测试先以缺少 `petpet.app.state` 失败，随后 `3 passed`。

## 第三阶段：双宠物聊天记忆

新增 `petpet.chat.memory`，聊天记忆现在按宠物身份持久化：

- 桌面宠物继续使用旧文件 `memory.json`，兼容已有玩家数据。
- 家园宠物使用 `memory-home.json`；首次使用且文件不存在时，只复制一次桌面记忆。
- 家园文件创建后，桌面历史、名字和用户画像的变化不会再覆盖它。
- `buddy_ai` 的旧调用默认仍指向 desktop；新增 profile 参数贯穿加载、保存、追加历史、自动摘要、改名和主动搭话时间记录。
- 聊天窗口在家园场景可见时选择 home，否则选择 desktop，并显示对应宠物的名字与历史。
- 清除一只宠物的记忆时，只删除该记忆实际引用的图片缩略图，不影响另一只宠物。
- 模型、系统提示词、额度、SSE 和网络请求逻辑本阶段均未修改。
