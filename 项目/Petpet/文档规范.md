# Petpet Obsidian 文档规范

本规范定义档案库（`D:\Github Desktop\My-Obsidian\项目\Petpet\`）的**归类、命名与写入规则**。仓库侧 `AGENTS.md` 的「Obsidian 实时记录」条款规定*何时必须写*，本规范规定*写到哪、叫什么、怎么写*。两者冲突时以本规范为准。

## 1. 目录职责

| 目录 | 职责 | 收录内容 |
|---|---|---|
| `Petpet 总档案.md` | 项目级总览与维护总结 | 定位与当前状态、功能总览、架构、版本演进表、路线与风险、维护清单、档案馆目录索引 |
| `文档规范.md`（本文件） | 归档规则本身 | 目录职责、命名规则、写入流程 |
| `源码启动.md` | 源码运行指引 | 环境、启动、调试入口 |
| `开发记录\` | 按日期的开发日志 | 单轮修复/调整/迭代/发版补录，一天一文件或多主题同文件追加 |
| `发布系统\` | 版本与发布、更新链路 | 发布说明、发布设计、发布实施计划/记录、版本规划索引、更新器/发布脚本相关 |
| `场景系统\` | 家园/小屋/装修 | 上述领域的设计、实施计划、实施记录、交互记录 |
| `宠物系统\` | 宠物本体 | 多宠物、动画、形象、行为类设计/实施文档 |
| `聊天系统\` | AI 聊天 | 聊天界面、代理、额度、知识库、人格类设计/实施文档 |
| `菜单系统\` | 菜单交互 | 快捷菜单、上拉菜单、气泡入口类文档 |
| `设置系统\` | 设置与教程 | 设置页、教程、偏好类文档 |
| `工程结构\` | 代码结构、工具、工程协作 | 重构设计/实施、参数调试器、仓库↔Obsidian 同步件（HANDOFF.md、AGENTS.md 副本）、迁移索引 |

## 2. 命名规则

### 2.1 开发记录（日志类，唯一需要日期前缀的目录）

格式：`YYYY-MM-DD 主题.md`

- 日期 = 该轮工作实际发生日；同日多轮可各自成文件，或并入当日同主题文件追加记录块。
- 主题写人话：改了什么，如 `2026-09-01 小屋按键两段式按压反馈`。
- 文件内部结构：背景 → 改动 → 验证 → 关联。

### 2.2 系统目录（场景/宠物/聊天/菜单/设置/工程结构）

格式：`主题 + 后缀.md`，后缀只允许以下四种：

| 后缀 | 用途 |
|---|---|
| `设计` | 方案、决策、拷问结论（为什么这么做） |
| `实施计划` | 分步执行计划（打算怎么做） |
| `实施记录` | 落地过程与验证结果（实际怎么做、结果如何） |
| `交互记录` | 交互演进与用户反馈轮次的沉淀 |

- 不加日期前缀；日期写在 frontmatter `updated:` 或正文标题里。
- 统一用「实施」，不写「实现」（历史文件已全部归一）。
- 主题与既有同族文件保持同词根（如 `商店信息与双列布局设计` ↔ `商店信息与双列布局实施计划`）。

### 2.3 发布系统

格式：`Petpet vX.Y.Z + 后缀.md`，后缀：`发布说明`（面向用户）、`发布设计`、`发布实施计划`、`发布实施记录`。固定入口：`版本规划与发布索引.md`。

### 2.4 总档案与其他根文件

根目录只允许：`Petpet 总档案.md`、`文档规范.md`、`源码启动.md`。新文件一律进目录，不再往根上放。

## 3. 归类判定（按顺序自上而下）

1. 与某个版本的发布/回滚/更新器有关 → `发布系统\`
2. 是方案/计划/实施沉淀，且属于某个功能领域 → 对应系统目录（场景/宠物/聊天/菜单/设置）
3. 代码结构、构建工具、参数调试器、仓库协作 → `工程结构\`
4. 其余（单轮 bug 修复、参数微调、视觉打磨、交互迭代、发版补录）→ `开发记录\` + 日期前缀

## 4. 总档案写入边界

**只写**：当前版本与状态行、功能总览、架构与资源总述、版本演进表、路线与风险、日常维护清单、档案馆目录索引。

**不写**：单轮开发日志（去开发记录）、发布细节（去发布系统）、具体设计决策（去系统目录）、逐轮用户反馈记录（去开发记录）。总档案的状态信息保持"最新一条"，历史靠版本演进表和各目录承载。

## 5. 写入流程（每轮开发动作的收尾步骤）

1. 按 §3 判定目录，按 §2 定文件名。
2. 写入内容四要素：**改了什么 / 为什么改 / 如何验证 / 关联链接**。
3. 若本轮改变了项目状态（版本、当前开发方向、验证结果），同步刷新总档案 §1 的状态行。
4. 发版轮次另在 `发布系统\` 落发布说明/实施记录，并更新 `版本规划与发布索引`。
5. 仓库 `HANDOFF.md`/`AGENTS.md` 有变更时，同步副本到 `工程结构\`。

## 6. 链接与维护义务

- 跨目录引用用带路径的 wikilink：`[[系统目录/文件名]]`、`[[开发记录/2026-09-01 某主题]]`；同目录内可用短名。
- **重命名或移动任何文件前，必须全库 grep 旧名并修复全部反向链接**；Obsidian 客户端内移动会自动改链，脚本/外部工具移动不会。
- 迁移、拆分、重命名等档案维护动作本身也记入 `开发记录\`（当日文件）。
- frontmatter 最小集：`title`、`type: project`、`status: active`、`updated: YYYY-MM-DD`、`summary`。
